## 2. タスク管理・更新フロー

ロードマップの更新や確認を行いたい場合は、AI エージェントに以下のように指示（またはコマンドを発行）してください。

### `/roadmap` コマンドの利用

チャット上で `/roadmap` と入力することで、専用のワークフローが起動します。

#### A. エージェントによる自律更新モード

特にオプションを指定せず `/roadmap` と入力すると、エージェントが自律的にソースコード (`src` や `tests`) を走査し、各タスクの実装状況（テストのSkip解除や新規機能の実装など）を確認します。完了していると判断されたタスクがあれば、エージェントが `roadmap_tasks.json` を更新し、その差分を Markdown で提案してくれます。

#### B. 人間用 UI モード

ユーザー自身でロードマップの全体像を俯瞰したい場合や、手動でステータス・メモを整理したい場合は、「UIを起動して」と指示するか `/roadmap --ui` （エージェントが解釈可能な指示）を送ってください。
エージェントがバックグラウンドで `tools/roadmap-ui` の開発サーバーを立ち上げるので、ブラウザから `http://localhost:5173` にアクセスして操作してください。UI上での変更はオートセーブ機能により自動的に `roadmap_tasks.json` へ反映・保存されます。

## 3. 優先度スコアリング基準 (Priority Scoring Criteria)

タスクの優先度 (Tier) は、JSON に保存されている各指標に基づき、動的に（UI 上などで）算出されます。

**指標定義 (1〜5点)**

- **$B$ (Blocker / 依存度)**: 他の実装やカーネルがブロックされる度合い（5: 完全ブロック / 1: 自己完結）
- **$D$ (Difficulty / 難易度)**: 実装難易度。高いほど難関・大設計（5: 大規模設計・リスク大 / 1: 極めて簡単・半日）
- **$G$ (Generality / 汎用性)**: コード内での出現頻度や利用される範囲（5: 日常的に全域で使用 / 1: 極めてニッチ）

**スコア計算式**
`Priority Score = (B * 4.0) + ((6 - D) * 3.0) + (G * 2.0)`

- **Tier 1 (最優先 / Score >= 36)**: ブロック度が高く、実装が容易（即効で他を解放）
- **Tier 2 (準優先 / Score >= 28)**: ブロック度は高いが、実装難易度も高い（早期に着手してパイプラインを疎通）
- **Tier 3 (並行タスク / Score >= 20)**: ブロック度は低いが、実装が容易（隙間時間に処理）
- **Tier 4 (後回し / Score < 20)**: ブロック度が低く、実装難易度も高い（性能チューニング、極小ニッチ構文など）
