# GSH0022: Unsafe field overwrite

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0022 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### Pointer Abandonment and Driver Memory Leaks
Reassigning a field that holds an active native GPU resource (e.g. `_buffer = new GpuBuffer<int>(200);`) overwrites the C# object reference, orphaning the underlying unmanaged VRAM allocation. The original allocation can never be freed through normal code paths.

## Cause

An active `IDisposable` field was overwritten with a new value without calling `.Dispose()` on the previous instance.

## How to Fix

Dispose of the existing instance before assigning the new instance.

## Examples

### Code with Warning / Error (Before)

```csharp
// Execution Context: Host (CPU)
public void Resize(int newSize)
{
    // Error GSH0022: Overwrites active _buffer without disposing old allocation
    _buffer = new GpuBuffer<int>(newSize);
}
```

### Corrected Code (After)

```csharp
// Execution Context: Host (CPU)
public void Resize(int newSize)
{
    // Correct: Dispose existing allocation before re-allocating
    _buffer?.Dispose();
    _buffer = new GpuBuffer<int>(newSize);
}
```
