# GSH0091: Stack array outlives its scope

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0091 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

C# keeps the array of `new int[4]` on the heap, where the garbage collector keeps it alive as long as something refers to it, and the storage of a `stackalloc` until the method returns. Device code has no heap, so G# keeps both as a C++ array of the thread: a local array (`int[] a = new int[4];`, `int[] a = { 1, 2 };`, `int[] a = [1, 2];`), the stack array of a span (`Span<int> s = stackalloc int[4];`) and the storage of a `stackalloc` elsewhere. That array ends with the innermost scope around it in the emitted C++: a block, a `switch` section, or the body statement of `if`, `else`, `for`, `foreach`, `while`, `do`, `using`, `fixed` or `lock`.

A value that points into the array after that scope ends points at memory that other variables reuse. The result would be wrong values with no error, so G# rejects the forms that could keep such a value.

## Cause

One of the following, where the value refers to a stack array:

- A stack array local (a local array, or a span declared over a stack array) is reassigned, or passed by `ref` or `out` (a C++ array cannot be assigned); `s = s.Slice(1)` is reported for this reason.
- The value is returned, also as `return ref a[0]`. A local function or lambda that returns a stack array of the method around it is reported as well, even when every call is inside the scope of the stack array: the emitted C++ lambda deduces its return type and would return a bare pointer without the length.
- The value is stored where it outlives the stack array: a local declared in a scope around the scope of the stack array (for example a variable declared before a block, a loop or a `switch` and assigned inside it), a parameter, a field or element of memory the method did not create, a `ref` local, or the target of a pointer.
- The value is passed to a call together with a `ref` or `out` argument that outlives the stack array, so that the callee could store it there (the rule C# calls "method arguments must match").

A value refers to a stack array when it is the stack array, a `stackalloc`, or a local that has been given one (through a declaration, an assignment, a tuple, a struct that holds it, or a call with a `ref` or `out` argument), including the value parameter of a local function or lambda that the method calls with one, and when it is an array, a span, a pointer or a struct holding one that is computed from such a value: a slice, a pointer offset, a conditional, a `with` expression, or the result of a call that receives such a value, or a variable inside such a stack array by `ref` / `in` (the callee may return its address). An index, a length or another argument whose type is not one of these does not carry the stack array, so `w = o.Slice(idx[0], idx.Length)` is not reported. The check is conservative within these positions: a value that only might refer to the stack array is reported as well.

## How to Fix

Keep the use inside the scope of the stack array, declare the stack array in the outer scope, or copy the elements into an array that the kernel receives.

## Examples

### Code with Warning / Error (Before)

```csharp
// Execution Context: G# Kernel (GPU)
[GpuDeviceFunction]
public static int[] MakeBuffer()
{
    int[] buffer = new int[4];
    // ❌ Error GSH0091: The stack array 'buffer' cannot be returned
    return buffer;
}

[GpuKernel]
public static void BadKernel(int[] output, int c)
{
    scoped Span<int> s = default;
    // ❌ Error GSH0091: the stackalloc ends with the body of the if
    if (c > 0) s = stackalloc int[4];
    output[0] = s.Length;
}
```

### Corrected Code (After)

```csharp
// Execution Context: G# Kernel (GPU)
[GpuDeviceFunction]
public static void FillBuffer(Span<int> buffer)
{
    buffer[0] = 1;
}

[GpuKernel]
public static void GoodKernel(int[] output, int c)
{
    // ✅ The stack array is declared in the scope that uses it
    Span<int> s = stackalloc int[4];
    if (c > 0) FillBuffer(s);
    output[0] = s[0];
}
```
