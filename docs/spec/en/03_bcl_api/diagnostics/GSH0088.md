# GSH0088: Device code of another assembly is not exported

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0088 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

A kernel and the device functions it calls are compiled into one native module per assembly (`Kassyi.GSharp.Kernels_<assembly>.g.cu` / `.g.cpp`). A device function of another assembly has no body in the consumer's compilation, so the G# generator of the declaring assembly records its transpiled C++ as assembly attributes (`[assembly: GpuDeviceExport]`), and the consumer copies the records that its kernels reach into its own module. nvcc and the C++ compiler then see one translation unit and inline across the assembly boundary as within one assembly.

Without a record, the consumer has nothing to copy: the native build would fail on an undefined name, and a struct constructor would run as a plain aggregate initialization that skips its body.

## Cause

GPU code calls a `[GpuDeviceFunction]` of a referenced assembly, or creates a struct of it through a constructor with a body (`new S(...)` or a target-typed `new(...)`), or reads a computed property of such a struct, and the assembly holds no record for it: it was not built with G#, it was built with `GSharpExportDeviceCode` set to `false`, it was built with a G# version that did not export device code, or its build could not transpile the function at all (it then reported GSH0048).

The same applies to what the recorded text calls in turn: when a library function calls a function of a third assembly that has no record, the use of the library function is reported with the name of that function. A constructor of a generic struct has a record only for the constructed types that the library itself uses (`Box<int>`, not `Box<float>`).

## How to Fix

- Rebuild the referenced assembly with this version of G#, with `GSharpExportDeviceCode` left at its default (`true`).
- If the assembly already exports device code, read the diagnostics of its build: a GSH0048 there means that G# could not transpile the function.
- For a constructor of a generic struct (`new Box<float>(...)`), the library records only the constructed types that its own device code uses; use one of those, or add a device function to the library that uses the construction.
- Or move the device function into the consuming assembly.

## Example

```csharp
// Library built with <GSharpExportDeviceCode>false</GSharpExportDeviceCode>
public static partial class LibMath
{
    [GpuDeviceFunction]
    public static int Twice(int x) => x * 2;
}

// Consumer
public static partial class Kernels
{
    [GpuKernel]
    public static void Run(int[] data)
    {
        data[ThreadIndex.X] = LibMath.Twice(data[ThreadIndex.X]); // Incorrect: GSH0088
    }
}
```
