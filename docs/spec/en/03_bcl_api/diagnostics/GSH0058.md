# GSH0058: GPU method name is a C++ keyword (temporary)

> [!IMPORTANT]
> **This is a temporary misuse-prevention diagnostic.** The names it rejects are valid C#, and G# intends to accept them. Once method names are renamed automatically ([#402](https://github.com/kassyi/Henicos/issues/402)), this diagnostic will be removed and the affected code will compile without changes.

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0058 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### Method Names Are Still Emitted Verbatim
The transpiler derives the C++ name of every parameter, local variable, label, local function, lambda parameter and struct member from its symbol, so these may use any legal C# name, including C++ keywords such as `register`, `template`, `union` or verbatim identifiers such as `@class`.

Method names live in the C++ global scope, where the transpiler still emits them verbatim. A method named after a C++ keyword (for example a device function `@class` or `template`) produces a C++ syntax error that NVRTC, nvcc, or the host C++ compiler reports against the generated file, far away from the C# source. This diagnostic moves the failure to the C# declaration until global names are renamed as well.

## Cause

The name of a `[GpuKernel]` or `[GpuDeviceFunction]` method is a C++20 keyword or alternative operator token (`and`, `or`, `not`, `xor`, ...). Verbatim identifiers such as `@class` are reported too, because their C# name is the bare keyword.

## How to Fix

Rename the method.

## Examples

### Code with Error (Before)

```csharp
// Execution Context: G# Kernel
[GpuDeviceFunction]
public static int template(int register) => register * 2; // ❌ GSH0058 on 'template'
```

### Corrected Code (After)

```csharp
// Execution Context: G# Kernel
[GpuDeviceFunction]
public static int Twice(int register) => register * 2; // ✅ parameter names may be C++ keywords
```
