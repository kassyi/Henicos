# GSH0031: Direct invocation of [GpuKernel] is prohibited

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0031 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### The Host-to-Device Transition Barrier

G# uses Roslyn Source Generators to automatically scaffold the complex boilerplate required for GPU execution (such as `cudaMalloc`, kernel launches, parameter marshaling, and execution context synchronization).

When you annotate a method with `[GpuKernel]`, the transpiler translates its body into a `.cu` (CUDA C++) kernel. Concurrently, the Source Generator creates a `LaunchXxx` method on the C# host side to bridge the CPU execution to the GPU hardware.

1. **GpuOnlyException Trap**: If you call a `[GpuKernel]` method directly from the CPU, it will execute standard C# code but crash as soon as it hits a GPU-intrinsic stub (e.g., `Gpu.GridStrideLoop()`, `ThreadIndex.X`), throwing a `GpuOnlyException`.
2. **Fail-Fast DX (Developer Experience)**: The `GSH0031` analyzer prevents this frequent mistake at compile time, guaranteeing that kernel dispatches correctly use the generated `Launch...` method and execute on the hardware GPU context.

## Cause

Host code runs or references a method marked with `[GpuKernel]` other than through its generated launcher. The
diagnostic is reported at the reference for each of these forms:

| Form | Example |
| :- | :- |
| A call, also inside a lambda in host code | `MathKernels.Process(data)` |
| A method group, in any conversion: assignment, delegate creation, cast, natural type, argument, event subscription, field initializer | `Action<float[]> f = MathKernels.Process;`, `Array.ForEach(arrays, MathKernels.Process)`, `Changed += MathKernels.Process;` |
| A function pointer | `delegate*<float[], void> p = &MathKernels.Process;` |
| A method that C# calls for a pattern: the `GetEnumerator`, `MoveNext`, `Current` or `Dispose` of a `foreach`, the `Deconstruct` of a deconstruction or a positional pattern, the `Add` of a collection initializer, the `GetAwaiter` of an `await` | `foreach (var x in range)` with a kernel `GetEnumerator(this Range r)` |
| An operator, a conversion operator or a property accessor marked with `[GpuKernel]` | `a + b`, `(int)n`, `Holder.Value` |

Generated code is checked as well: a `*.g.cs` file, a file with an `<auto-generated/>` header and the output of other
source generators. Only the code that the G# generators themselves add is left out.

Not reported:

- A reference in device code (a kernel, a device function, or a lambda or local function inside one). A call of a kernel
  there is [GSH0003](GSH0003.md).
- `nameof(MathKernels.Process)`, which does not run the method.
- A call that C# removes: the method has `[Conditional("SYMBOL")]` and none of its symbols is defined in the file of the
  call, or it is a partial method without an implementation. The arguments of such a call are removed with it.

### What the check cannot see

Reflection, `dynamic` and an assembly that does not reference the G# analyzers reach a kernel without a diagnostic. The
kernel body then runs once on the calling thread as ordinary C#, without a GPU launch, and throws `GpuOnlyException` at
the first GPU intrinsic (the side effects before it stay).

## How to Fix

Change the method call to use the automatically generated `Launch{MethodName}` method instead, providing the necessary `GridDimension` and `BlockDimension` configuration parameters.

To run the kernel's C# body on the host, for example as the reference result of a test, do not call the method
either: launch it through the same `Launch{MethodName}` method inside
[`GpuExecution.Use(KernelExecution.CSharp)`](../execution_context/GpuExecution.md). The launcher then runs the method
once per GPU thread, one thread after another, with the coordinates of each thread set, and rejects a kernel that
needs the other threads (a barrier, a warp intrinsic, shared memory).

```csharp
// Execution Context: Host Only
using (GpuExecution.Use(KernelExecution.CSharp))
{
    // ✅ Correct: the C# value of each of the 100 threads
    MathKernels.LaunchProcessHeavySimulation(data, result, data.Length, blockDimX: 100);
}
```

## Examples

### Code with Warning / Error (Before)

```csharp
// Execution Context: Host Only
public class SimulationRunner
{
    public void Run()
    {
        float[] data = new float[100];

        // ❌ Error GSH0031: Do not call [GpuKernel] method 'ProcessHeavySimulation' directly. Use the generated 'LaunchProcessHeavySimulation' launcher method instead.
        MathKernels.ProcessHeavySimulation(data, data, data.Length);
    }
}

public static class MathKernels
{
    [GpuKernel]
    public static void ProcessHeavySimulation(float[] data, float[] result, int length)
    {
        /* GPU Logic */
    }
}
```

### Corrected Code (After)

```csharp
// Execution Context: Host Only
public class SimulationRunner
{
    public void Run()
    {
        float[] data = new float[100];

        // ✅ Correct: Calls the source-generated Launch wrapper
        MathKernels.LaunchProcessHeavySimulation(
            data,
            data,
            data.Length,
            gridDimX: 1,
            blockDimX: 256);
    }
}
```
