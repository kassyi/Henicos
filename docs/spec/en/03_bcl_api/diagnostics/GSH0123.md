# GSH0123: A generic device function cannot be compiled for the GPU

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0123 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

A type parameter has no C++ type: the C++ and CUDA output of a function depends on the concrete type of every value
(integer semantics, conversions, the layout of a struct). G# is to compile a generic device function once for each set
of type arguments that the kernels use, as a closed function of its own. Until then, G# does not compile a generic
declaration that uses its type parameters. It reports this diagnostic once, at the name of the function, instead of one
diagnostic for each use of a type parameter in its body, and it writes neither the C++ nor the CUDA function, nor, for a
function that waits at a barrier, the frame and the managed state machine of the CPU paths.

A device function whose type parameters appear neither in its signature nor in its body does not depend on them: it is
compiled once, as one function for every type argument, and is not reported. A type argument that it passes on to
another such function does not count as a use.

Other generic forms:

- Generic iterators (`IEnumerable<T>` with `yield`) are reported by [GSH0070](GSH0070.md).
- Generic kernels are reported by [GSH0111](GSH0111.md).
- Generic structs and their constructors are not affected: each closed struct type is written as a type of its own.
- A device function that declares no type parameter of its own but is a member of a generic type is not reported here.
  When it uses the type parameter of its type, each use is reported as [GSH0003](GSH0003.md) ('unsubstituted type
  parameter'), and one that waits at a barrier also stops the generator with [GSH0048](GSH0048.md), until G# compiles
  generic device functions per instance.

## Cause

A method marked `[GpuDeviceFunction]` declares type parameters and names one of them: in a parameter type, in its
return type, or anywhere in its body, except as a type argument of a call to a generic function that does not use its
own type parameters itself. A function that only passes its type parameter on to such a function (`F<T>` calling
`G<T>(x)`, where `G` does not use its type parameter) is compiled once, like the function it calls; one that passes it
on to a function that is reported is reported as well. Functions that only pass their type parameter to each other in a
cycle (`Ping<T>` calling `Pong<T>`, which calls `Ping<T>`) are compiled once each.

## How to Fix

Write the function for the types that the kernels use, without type parameters.

## Examples

### Code with an Error (Before)

```csharp
public static partial class PickKernels
{
    [GpuDeviceFunction]
    public static T Pick<T>(T a, T b, bool first) where T : unmanaged => first ? a : b;   // GSH0123 at 'Pick'

    [GpuKernel]
    public static void Run(int[] xs)
    {
        int tid = ThreadIndex.X;
        xs[tid] = Pick(xs[tid], 0, tid % 2 == 0);
    }
}
```

### Corrected Code (After)

```csharp
public static partial class PickKernels
{
    [GpuDeviceFunction]
    public static int Pick(int a, int b, bool first) => first ? a : b;   // OK

    [GpuKernel]
    public static void Run(int[] xs)
    {
        int tid = ThreadIndex.X;
        xs[tid] = Pick(xs[tid], 0, tid % 2 == 0);
    }
}
```
