# GSH0054: An intrinsic is not implemented by the target dialect

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0054 |
| **Category** | GSharpTranspiler |
| **Severity** | Warning |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### Some GPU Instructions Have No CPU Meaning
A few intrinsics stand for hardware that only the GPU has. The CPU dialect (`StandardCpp`) cannot give the result the GPU gives for them, so it does not implement them:

| Intrinsic | Why the CPU dialect does not implement it |
| :--- | :--- |
| `Gpu.InlinePtx` | Raw PTX has no equivalent outside the GPU; only dialects with the `InlineAssembly` capability (CUDA) emit it. |
| `Gpu.MBarrierInit`, `Gpu.MBarrierArrive`, `Gpu.MBarrierWait` | The asynchronous barrier object of shared memory (PTX `mbarrier`). |
| `Wmma.Fill`, `Wmma.Load`, `Wmma.Store`, `Wmma.MultiplyAccumulate` | Tensor Core fragments, whose layout across the lanes of a warp is the hardware's. |
| `Gpu.ConvertToSharedMemory` | The address of the shared state space window, which the CPU does not have. |

The native API definitions (`src/NativeApi/*.yml`) list the dialects that do not implement an intrinsic in its `unsupported` column (`unsupported: [Cpu]`); `Gpu.InlinePtx` follows the capabilities of the dialect.

Silently skipping the call is unsafe: these intrinsics have side effects (writing a register, memory or a barrier), so a skipped call would let the CPU kernel return a different result from the GPU kernel without any signal. Writing the native name would fail the C++ build without a location in your source.

Instead, the transpiler replaces the call with `__gsharp_unsupported(...)` (a call with a value gives the default value of its type, and its arguments are not evaluated). If the call is reached on the CPU dialect, the runtime error channel records the first error across OpenMP worker threads, halts remaining work early, and propagates the failure across the native boundary so the host launch wrapper throws a managed `System.NotSupportedException`. The managed CPU path throws `GpuOnlyException` from the intrinsic itself.

## Cause

GPU code calls an intrinsic that the target dialect does not implement.

## How to Fix

Keep the call out of any code path that the CPU dialect executes, or provide a portable implementation for it. The warning is expected when a kernel that uses the intrinsic is built for the CPU dialect but never executed there.

## Examples

### Code with Warning (Before)

```csharp
// Execution Context: G# Kernel (CPU dialect)
[GpuKernel]
public static void ReadLaneKernel(uint[] data)
{
    uint reg = data[0];
    // Warning GSH0054 on the CPU dialect; throws NotSupportedException at runtime if executed
    Gpu.InlinePtx($"mov.u32 {reg}, 42;");
    data[0] = reg;
}
```

### Corrected Code (After)

```csharp
// Execution Context: G# Kernel
[GpuKernel]
public static void ReadLaneKernel(uint[] data)
{
    // Portable implementation that works on every dialect
    data[0] = 42;
}
```
