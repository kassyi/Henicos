# GSH0029: Manual unmanaged allocation detected

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0029 |
| **Category** | GSharpTranspiler |
| **Severity** | Warning |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### Direct VRAM Allocation Hazards
`Gpu.Unsafe.Malloc(int size)` allocates a raw block from the device heap (CUDA `malloc` in a kernel; the C runtime `malloc` in the C++ dialect) and returns a `void*`. The block has no RAII wrapper, garbage collection tracking, or automatic disposal, and the device heap is small by default and shared by all threads. Only a call to `Malloc` from a `[GpuKernel]` or `[GpuDeviceFunction]` reports this diagnostic; `Gpu.Unsafe.Free(void*)` does not.

This diagnostic is a **Warning** (not an error). It alerts developers that they are operating with raw device pointers:
- If `Gpu.Unsafe.Free()` is omitted or bypassed (e.g., by an early `return` before the free call), the block remains leaked until the process terminates.
- Raw pointers (`void*`) do not implement `IDisposable`, so they cannot participate in C# `using` declarations.

If every path of the kernel pairs `Malloc` with `Free`, the allocation does not leak. However, G# issues this warning to advise using managed RAII wrappers wherever possible.

## Cause

A low-level manual device memory allocation API (`Gpu.Unsafe.Malloc`) was called directly.

## How to Fix

There are two valid approaches depending on your architectural requirements:

1. **Recommended (Type-safe RAII):** Replace manual raw pointer allocation with `GpuBuffer<T>`, which implements `IDisposable` and guarantees cleanup upon exiting scope via `using`.
2. **Low-level allocation with guaranteed cleanup:** If raw pointers are required (such as in custom ring buffers or pooling allocators), make sure every path that follows `Gpu.Unsafe.Malloc` calls `Gpu.Unsafe.Free(ptr)`, and suppress the warning via `#pragma warning disable GSH0029`.

## Examples

### Code with Warning (Before / Problematic)

```csharp
// Execution Context: G# Kernel (GPU)
using Kassyi.GSharp.Core;

[GpuKernel]
public static unsafe void ProcessUnsafeData(int[] output)
{
    // ⚠️ Warning GSH0029: Manual unmanaged allocation detected.
    // Hazard: every path that skips Free() leaks the block until the process ends!
    int* block = (int*)Gpu.Unsafe.Malloc(16);

    block[0] = ThreadIndex.X;
    output[ThreadIndex.X] = block[0];

    Gpu.Unsafe.Free(block);
}
```

### Corrected Code (After)

#### Option 1 (Recommended): Use `GpuBuffer<T>` with `using` (RAII)

```csharp
// Execution Context: Host (CPU)
using Kassyi.GSharp.Runtime;

public void ProcessSafeData()
{
    // ✅ Zero warnings: GpuBuffer<T> implements IDisposable.
    // Automatically freed deterministically upon leaving the scope, even on exceptions.
    using var buffer = new GpuBuffer<byte>(1024);

    DoWork(buffer);
}
```

#### Option 2: Verified Pairing of `Malloc` and `Free`

```csharp
// Execution Context: G# Kernel (GPU)
using Kassyi.GSharp.Core;

[GpuKernel]
public static unsafe void ProcessLowLevelData(int[] output)
{
#pragma warning disable GSH0029 // Verified: the block is freed below
    int* block = (int*)Gpu.Unsafe.Malloc(16);
#pragma warning restore GSH0029

    // ✅ Safe: the only exit of the kernel frees the block
    block[0] = ThreadIndex.X;
    output[ThreadIndex.X] = block[0];
    Gpu.Unsafe.Free(block);
}
```
