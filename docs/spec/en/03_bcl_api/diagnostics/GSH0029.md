# GSH0029: Manual unmanaged allocation detected

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0029 |
| **Category** | GSharpTranspiler |
| **Severity** | Warning |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### Direct VRAM Allocation Hazards
Low-level methods like `Gpu.Unsafe.Malloc()` allocate raw device memory (`cudaMalloc`) without RAII wrappers, garbage collection tracking, or automatic disposal. 

This diagnostic is a **Warning** (not an error). It alerts developers that they are operating with raw device pointers:
- If `Gpu.Unsafe.Free()` is omitted or bypassed (e.g., due to an unhandled exception before the free call), the VRAM remains leaked until the process terminates.
- Raw pointers (`IntPtr`) do not implement `IDisposable`, so they cannot participate in C# `using` declarations.

If you properly pair `Malloc` with `Free` inside a `try ... finally` block, the allocation is safe and will not leak memory. However, G# issues this warning to advise using managed RAII wrappers wherever possible.

## Cause

A low-level manual device memory allocation API (`Gpu.Unsafe.Malloc`) was called directly.

## How to Fix

There are two valid approaches depending on your architectural requirements:

1. **Recommended (Type-safe RAII):** Replace manual raw pointer allocation with `GpuBuffer<T>`, which implements `IDisposable` and guarantees cleanup upon exiting scope via `using`.
2. **Low-level allocation with guaranteed cleanup:** If raw pointers are required (such as in custom ring buffers or pooling allocators), strictly wrap the pointer in a `try ... finally` block calling `Gpu.Unsafe.Free(ptr)`, and suppress the warning via `#pragma warning disable GSH0029`.

## Examples

### Code with Warning (Before / Problematic)

```csharp
// Execution Context: G# Kernel (GPU)
using System;
using Kassyi.GSharp.Runtime;

[GpuKernel]
public void ProcessUnsafeData()
{
    // ⚠️ Warning GSH0029: Manual unmanaged allocation detected.
    // Hazard: If DoWork() throws an exception, Free() is never called and VRAM is leaked!
    IntPtr ptr = Gpu.Unsafe.Malloc(1024);
    
    DoWork(ptr);

    Gpu.Unsafe.Free(ptr);
}
```

### Corrected Code (After)

#### Option 1 (Recommended): Use `GpuBuffer<T>` with `using` (RAII)

```csharp
// Execution Context: Host (CPU)
using Kassyi.GSharp.Runtime;

public void ProcessSafeData()
{
    // ✅ Zero warnings: GpuBuffer<T> implements IDisposable.
    // Automatically freed deterministically upon leaving the scope, even on exceptions.
    using var buffer = new GpuBuffer<byte>(1024);

    DoWork(buffer);
}
```

#### Option 2: Guaranteed Cleanup with `try ... finally`

```csharp
// Execution Context: G# Kernel (GPU)
using System;
using Kassyi.GSharp.Runtime;

[GpuKernel]
public void ProcessLowLevelData()
{
#pragma warning disable GSH0029 // Verified: Guaranteed cleanup via try-finally
    IntPtr ptr = Gpu.Unsafe.Malloc(1024);
#pragma warning restore GSH0029

    try
    {
        DoWork(ptr);
    }
    finally
    {
        // ✅ Safe: Always freed even if DoWork throws an exception
        Gpu.Unsafe.Free(ptr);
    }
}
```
