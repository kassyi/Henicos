# GSH0053: Native API definition violates the schema

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0053 |
| **Category** | GSharpCompiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### Generated Code Must Be Correct by Construction
A native API definition is turned directly into C# declarations (`[DllImport]` bindings or kernel launchers). Values
that become symbols are validated before any code is emitted so that a typo surfaces as a precise error on the YAML
line rather than as a confusing compiler error inside a generated file.

Each definition binds exactly one kind of native code:

| Key | Binding | Generated code |
| :--- | :--- | :--- |
| `libraryName` | Host shared library (`.dll` / `.so`) | `extern` methods with `[DllImport]`, plus a `DllImportResolver` when `libraryNames` or a path is used |
| `moduleName` | Device module (`.fatbin` / `.cubin` / `.ptx`) | Launchers that load the kernel named by `entryPoint` and call `cuLaunchKernel` |

## Cause

One of the following:

- `namespace`, `className`, a method `name`, or a parameter `name` / `type` is missing.
- A `namespace`, `className`, method or parameter name is not a valid C# identifier.
- Both `libraryName` and `moduleName` are specified, or neither is.
- `libraryNames` is specified without `libraryName`.
- A method of a `moduleName` definition declares a `returnType` other than `void` (kernels cannot return values).
- A parameter of a `moduleName` definition has a type the launcher cannot pass to the kernel. The type is read with the
  C# parser, so `float[ ]` and `float []` are the same array as `float[]`. Reported: a type that does not parse;
  modifiers other than `ref`, `out`, `in`, `ref readonly` (each optionally after `scoped`) or `params`; a `ref`, `out`
  or `in` pointer, array or launch setting; `Nullable<T>` (`int?`, `Nullable<int>`), a jagged array (`float[][]`);
  an array of pointers; a reference type spelled `string`, `object`, `dynamic`, `String`,
  `Object` or `Array` (with or without `System.`), or an array of them; a tuple (`(int, float)`, `ValueTuple<...>`),
  `DateTime` or `DateTimeOffset`, or an array of them, whose `LayoutKind.Auto` lets the runtime reorder the fields; a
  ref struct (`Span<T>`, `ReadOnlySpan<T>`, or `scoped` alone); `params` on a type that is not a
  one-dimensional array; a launch setting name with the wrong type (`gridDimX`, `gridDimY`, `gridDimZ`, `blockDimX`,
  `blockDimY`, `blockDimZ` and `sharedMemBytes` must be `uint`, `ushort`, `byte` or `char`, `stream` must be `IntPtr`
  or `nint`, also spelled with their `System.` names). A kernel takes unmanaged values, pointers and arrays of
  unmanaged elements: an array, also a nullable (`float[]?`) or multidimensional one (`float[,]`, copied in row-major
  order), goes through a device buffer that is copied back after the launch; null arrives as a null pointer for an
  array written nullable (`float[]?`, `float[,]?`) and throws `ArgumentNullException` before the launch for another; a `ref`, `out` or `in` value goes through a one-element device buffer, copied in unless it is `out` and
  back unless it is `in` or `ref readonly` (an `out` value starts from `default`). Any other class
  (`Action`, a class of the project) cannot be told from a struct by its name: the generated launcher takes the
  argument's address through a method constrained to unmanaged types, so a class fails to compile there with CS8377.
  A struct of the project with `LayoutKind.Auto` cannot be told by its name either, and is passed as the runtime lays
  it out: declare the structs a YAML binding passes with sequential or explicit layout, or use `[CudaImport]`, which
  reports them (GSH0110).
- A method's `className` is not a class name or a dotted path of nested classes (`Outer.Inner`).
- A method declares `typeParameters`. `[DllImport]` bindings and kernel launchers cannot be generic; only the
  built-in GPU intrinsic definitions of G# use this key, and the top-level `classes` list as well.
- A method declares `xmlDoc` together with `summary`, `returnDescription` or a `description`; `xmlDoc` holds the whole
  documentation.
- A method declares `managed` in a `libraryName` or `moduleName` definition, or its value is not a dotted name
  (`ManagedAtomics.Add`). The key is internal to the built-in GPU intrinsic definitions of G#: the generated stub
  forwards its arguments to `Kassyi.GSharp.Core.<name>`, usually an internal member that runs the intrinsic on the
  managed CPU path.
- `isUnsafe` is not `true` or `false`; `methods` / `parameters` is not a sequence.
- Two definitions in the same project declare the same `namespace` + `className`.

## How to Fix

Follow the message, which names the offending key. Split a definition that mixes host and device bindings into two
files.

## Examples

### Code with Warning / Error (Before)

```yaml
namespace: MyApp.Native
className: MyKernels
moduleName: ./native/my_kernels.fatbin
methods:
  - name: Reduce
    # ❌ Error GSH0053: 'returnType' must be 'void' for module (kernel) bindings
    returnType: float
    parameters:
      - { name: data, type: "float[]" }
```

### Corrected Code (After)

```yaml
namespace: MyApp.Native
className: MyKernels
moduleName: ./native/my_kernels.fatbin
methods:
  - name: Reduce
    entryPoint: reduce_kernel
    # ✅ Correct: results are written to an output array
    parameters:
      - { name: data, type: "float[]" }
      - { name: result, type: "float[]" }
```
