# GSH0011: Macro lambda requires a parameter

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0011 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### AST Rewriting and Loop Induction Variables
G# provides high-level loop macros such as `Gpu.GridStrideLoop(length, i => { ... })` that compile down to optimized native CUDA `for` loops. The AOT transpiler analyzes the lambda AST, extracts the loop body, and binds the loop induction variable (e.g. `int i = blockIdx.x * blockDim.x + threadIdx.x;`) to the lambda parameter.

If a developer passes a parameterless lambda `() => { ... }`, the transpiler cannot substitute the iteration index within the loop body, making loop parallelization mathematically impossible.

## Cause

A parameterless lambda expression was passed to a macro that requires a loop variable parameter.

## How to Fix

Specify the loop variable parameter in the lambda declaration.

## Examples

### Code with Warning / Error (Before)

```csharp
// Execution Context: G# Kernel (GPU)
[GpuKernel]
public static void BadKernel(int length)
{
    // Error GSH0011: Lambda must declare a parameter for the loop variable
    Gpu.GridStrideLoop(length, () =>
    {
        // No loop index available!
    });
}
```

### Corrected Code (After)

```csharp
// Execution Context: G# Kernel (GPU)
[GpuKernel]
public static void GoodKernel(int length)
{
    // Correct: Lambda parameter 'i' receives the calculated grid-stride index
    Gpu.GridStrideLoop(length, i =>
    {
        // Safely access element i
    });
}
```
