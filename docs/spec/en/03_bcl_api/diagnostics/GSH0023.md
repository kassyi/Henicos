# GSH0023: Property getter side-effect

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0023 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### Framework Design Guidelines and Accidental Leaks
According to Microsoft Framework Design Guidelines, property getters must be lightweight, idempotent, and free of observable side effects. Allocating a disposable GPU resource inside a getter is hazardous because tooling (e.g. visual debuggers, serialization engines, property watchers) calls getters repeatedly without disposing the returned objects, exhausting VRAM.

## Cause

A property getter instantiated an `IDisposable` GPU resource via `new`.

## How to Fix

Replace the property getter with an explicit factory method (`CreateBuffer()`).

## Examples

### Code with Warning / Error (Before)

```csharp
// Execution Context: Host (CPU)
// ❌ Error GSH0023: Allocates disposable resource in a property getter
public GpuBuffer<int> ScratchBuffer => new GpuBuffer<int>(256);
```

### Corrected Code (After)

```csharp
// Execution Context: Host (CPU)
// ✅ Correct: Explicit method communicates that a new native resource is created
public GpuBuffer<int> CreateScratchBuffer() => new GpuBuffer<int>(256);
```
