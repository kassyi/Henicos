# GSH0037

## Divergent barriers are prohibited

|  |  |
| :--- | :--- |
| **Category** | GSharpTranspiler |
| **Severity** | Error |

## Cause

`Gpu.SyncThreads()` was placed inside a thread-dependent conditional branch (e.g., an `if` statement whose condition relies on `threadIdx`).

The same applies to a call to a `[GpuDeviceFunction]` that reaches `Gpu.SyncThreads()` or `Gpu.SyncGrid()`, directly or through other device functions, to the body of a loop, and to an operand that only some threads evaluate: the right operand of `&&`, `||` and `??`, and the branches of `?:`. A call that reaches only warp shuffles may sit in a branch, because a shuffle takes the mask of the threads that reach it.

The diagnostic is reported only when the condition is **thread-variant**, that is, when it may have different values in different threads of a block. A condition that every thread of the block evaluates to the same value, such as a kernel argument, is allowed.

## Rule Description

In the CUDA programming model (SIMT), threads in a block execute concurrently. A barrier synchronization function like `Gpu.SyncThreads()` must be executed by *all* threads in the block. If some threads reach the barrier and others do not due to a conditional branch, it results in undefined behavior or a deadlock on the physical GPU.

Furthermore, during CPU testing (using the G# CPU Emulation Context), divergent barriers prevent the Bulk Synchronous Parallel (BSP) state machine from advancing, causing an immediate deadlock. The G# Roslyn Analyzer statically detects and blocks this to guarantee correctness across both environments.

### Thread-variant values

The analyzer follows the values in the body of the kernel or device function. A value is thread-variant when it depends on:

- `ThreadIndex`, `Gpu.LaneId()`, `Gpu.WarpId()`, `Gpu.SmId()` or the clock;
- the result of an atomic operation or a warp-level operation (shuffle, vote, match, reduce);
- a local that is assigned a thread-variant value, or assigned inside a branch or loop with a thread-variant condition;
- the result, or a `ref` / `out` argument, of a call to a device function whose body makes it thread-variant, given which arguments are thread-variant. A device function that takes each thread's value and returns a value read from shared memory with a uniform index (for example the result of a block reduction) returns a uniform value;
- a parameter of a lambda or a local function.

Two assumptions keep the analysis within one method, and both can hide a divergent barrier:

- A parameter of a kernel or a device function is uniform. Every thread of a kernel receives the same arguments; the arguments passed to a device function are checked at each call site only for the value it returns.
- An array or shared memory element read with a uniform index is uniform, because the threads read the same memory after a barrier.

A `return`, `break` or `continue` under a thread-variant condition before a barrier also diverges, but it is not detected.

## How to Fix

Ensure that all calls to `Gpu.SyncThreads()`, and all calls to device functions that reach it, are located in the uniform control flow of the kernel, where all threads within the block are guaranteed to reach the barrier.

## Examples

### Code with Warning / Error (Before)

```csharp
[GpuKernel]
public static void Kernel(Dim3 threadIdx)
{
    // ...
    if (threadIdx.X < 16) 
    {
        // ❌ Error GSH0037: Only some threads execute this barrier
        Gpu.SyncThreads();
    }
}
```

### Corrected Code (After)

```csharp
[GpuKernel]
public static void Kernel(Dim3 threadIdx)
{
    // ...
    if (threadIdx.X < 16) 
    {
        // Perform work for the first 16 threads
    }
    
    // ✅ Correct: All threads execute the barrier uniformly
    Gpu.SyncThreads();
}
```
