# GSH0037

## Barrier in a lambda or local function that the CPU dialects do not split

|  |  |
| :--- | :--- |
| **Category** | GSharpTranspiler |
| **Severity** | Error |

## Cause

`Gpu.SyncThreads()` or `Gpu.SyncGrid()` is written in a lambda other than the body of `Gpu.ForUnroll` or `Gpu.SyncGrid(body)` (for example the body of `Gpu.GridStrideLoop` or `Gpu.SingleThread`, or a lambda stored in a delegate), or in a local function.

A barrier that only some threads reach because of a branch (an `if`, a loop, `&&`, `||`, `??`, `?:`, or a call to a device function whose barrier diverges) is the warning [GSH0083](GSH0083.md), not this error: which threads take a branch depends on the launch configuration and on run-time values, which the compiler does not know.

## Rule Description

The CPU dialects split a kernel into phases at each barrier and resume it there, but only in the statements of the kernel body and of the bodies of `Gpu.ForUnroll` and `Gpu.SyncGrid(body)`, which are expanded in place. A barrier inside any other lambda or inside a local function cannot be resumed, so it would not wait for the other threads of the block; the kernel would compute different results on the CPU than on the GPU in every launch. The error does not depend on the launch.

## How to Fix

Move the barrier into the kernel body (or the body of `Gpu.ForUnroll` / `Gpu.SyncGrid(body)`), after the lambda or the call of the local function.

## Examples

### Code with Error (Before)

```csharp
[GpuKernel]
public static void Kernel(int[] data, int n)
{
    Gpu.GridStrideLoop(n, i =>
    {
        data[i] += 1;
        Gpu.SyncThreads(); // Error GSH0037: the body of GridStrideLoop is not split into phases
    });
}
```

### Corrected Code (After)

```csharp
[GpuKernel]
public static void Kernel(int[] data, int n)
{
    Gpu.GridStrideLoop(n, i =>
    {
        data[i] += 1;
    });

    Gpu.SyncThreads(); // every thread of the block reaches it after the loop
}
```
