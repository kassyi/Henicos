# GSH0016: Unroll factor must be a non-negative compile-time constant

## Details

| Property               | Value            |
| :--------------------- | :--------------- |
| **Diagnostic ID**      | GSH0016          |
| **Category**           | GSharpTranspiler |
| **Severity**           | Error            |
| **Enabled by Default** | Yes              |

## Why This Rule Exists (Architectural Context)

### CUDA Loop Unroll Directive Grammar

`Gpu.Hint.Unroll(factor)` maps directly to CUDA C++'s `#pragma unroll <factor>`.
The NVIDIA CUDA compiler (`nvcc`) syntax requires the unroll factor to be an integer literal $\ge 0$:

- `0`: Compiler heuristically determines whether and how much to unroll.
- `> 0`: Explicitly unrolls the loop by the specified constant factor.
  Negative numbers are syntactically invalid in `#pragma unroll` and will cause compilation failure.

## Cause

A negative integer or non-constant expression was passed to `Gpu.Hint.Unroll(factor)`.

## How to Fix

Pass a non-negative integer constant (`0` or greater).

## Examples

### Code with Warning / Error (Before)

```csharp
// Execution Context: G# Kernel (GPU)
[GpuKernel]
public static void BadKernel()
{
    // ❌ Error GSH0016: Negative unroll factor is invalid in CUDA
    Gpu.Hint.Unroll(-1);
    for (int i = 0; i < 8; i++) { }
}
```

### Corrected Code (After)

```csharp
// Execution Context: G# Kernel (GPU)
[GpuKernel]
public static void GoodKernel()
{
    // ✅ Correct: Positive compile-time constant specifies unroll factor
    Gpu.Hint.Unroll(4);
    for (int i = 0; i < 8; i++) { }
}
```
