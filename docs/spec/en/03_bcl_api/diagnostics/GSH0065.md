# GSH0065

## Shared memory declarations on one line share a buffer in managed execution

|  |  |
| :--- | :--- |
| **Category** | GSharpTranspiler |
| **Severity** | Warning |

## Cause

Two `new SharedMemory<T>(...)` expressions are written on the same line of a file, in the same method or in methods with the same name (overloads).

## Rule Description

A `SharedMemory<T>` declaration is one buffer per thread block, like a CUDA `__shared__` variable (see [SharedMemory&lt;T&gt;](../memory/SharedMemory.md#one-buffer-per-declaration-per-block)). The CPU and managed runtimes look the buffer up by a key of the declaration.

Under managed execution, a device function that never reaches a barrier runs as ordinary C#, without the compiler's rewrite. There the `SharedMemory<T>` constructor knows its caller only through `[CallerFilePath]`, `[CallerLineNumber]` and `[CallerMemberName]`: the file, the line and the method name. C# passes nothing that tells two declarations on one line apart, or two overloads apart. Such declarations share one buffer in managed execution, while they get two buffers on the GPU and on the CPU dialect, so the results differ.

The code is correct on the GPU, so this is a warning.

## How to Fix

Write each `SharedMemory<T>` declaration on its own line.

## Examples

### Code with Warning / Error (Before)

```csharp
[GpuDeviceFunction]
public static int SumPair(int value)
{
    // ⚠️ Warning GSH0065: managed execution gives both declarations the same buffer
    var left = new SharedMemory<int>(32); var right = new SharedMemory<int>(32);
    // ...
}
```

### Corrected Code (After)

```csharp
[GpuDeviceFunction]
public static int SumPair(int value)
{
    // ✅ Correct: one declaration per line
    var left = new SharedMemory<int>(32);
    var right = new SharedMemory<int>(32);
    // ...
}
```
