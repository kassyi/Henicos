# GSH0064: Kernel parameters exceed the parameter space limit

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0064 |
| **Category** | GSharpTranspiler |
| **Severity** | Warning |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### Parameter Space Limit Overflow
In NVIDIA CUDA, kernel parameters are passed via a specialized constant memory region called the **Parameter Space**. On CUDA architectures prior to Volta, or when maintaining target compatibility across architectures, the maximum total parameter space size for a kernel launch is **4,096 bytes** (4 KB). On CUDA 12.1+ targeting Volta or newer architectures, this limit can be up to 32 KB, but exceeding 4,096 bytes will cause compilation failures with `nvcc` when targeting standard device models.

Passing moderately sized structs by value is completely valid and efficient in CUDA because uniform reads of the parameter space are broadcast to all threads in a warp through constant memory cache. However, when the combined size of all parameters in a `[GpuKernel]` exceeds 4,096 bytes, the build will fail during PTX/fatbin compilation.

GSH0064 warns early at compile-time before `nvcc` compilation fails. Device functions (`[GpuDeviceFunction]`) use register/stack parameter passing and are not subject to kernel parameter space limits.

## Cause

The total footprint of the emitted `__global__` kernel parameter list, calculated in declaration order with field and parameter alignment, exceeds 4,096 bytes.

The total size is computed as follows:
- For `ref` / `out` / `in` parameters, an 8-byte pointer is used (size 8, alignment 8).
- For array-like parameters (`T[]`, `Span<T>`, `Memory<T>`, `ArraySegment<T>`, `ImmutableArray<T>`, ...), the `GSharpArray<T>` header is used: a device pointer, the length, and padding (size 16, alignment 8).
- For value parameters, CUDA layout rules compute struct size and alignment (including nested field padding).
- Each parameter is aligned up to its required alignment before adding its size.
- If the kernel method has a non-void return type, an implicit hidden result pointer (8 bytes, alignment 8) is added at the end of the parameter list.

## How to Fix

Pass large data structures through a one-element array (`T[]`), a `Span<T>`, or a device buffer pointer instead of by value.

## Examples

### Code with Warning (Before)

```csharp
// Execution Context: G# Kernel (GPU)
public struct LargeDataBlock // Size = 4096 bytes
{
    public long Field0;
    // ... 512 long fields ...
}

public static partial class Kernels
{
    [GpuKernel]
    // ⚠️ Warning GSH0064: Total parameter space is 16 + 4096 = 4112 bytes (> 4096 bytes)
    public static void OversizedKernel(int[] data, LargeDataBlock config)
    {
        data[ThreadIndex.X] = (int)config.Field0;
    }
}
```

### Corrected Code (After)

```csharp
// Execution Context: G# Kernel (GPU)
public static partial class Kernels
{
    [GpuKernel]
    // ✅ Correct: Passing config via an array transfers only a 16-byte array header (device pointer and length)
    public static void FixedKernel(int[] data, LargeDataBlock[] config)
    {
        data[ThreadIndex.X] = (int)config[0].Field0;
    }
}
```
