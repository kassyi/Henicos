# GSH0064: Kernel parameters exceed the parameter space limit

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0064 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### Parameter Space Limit Overflow
In NVIDIA CUDA, kernel parameters are passed through a constant memory region called the **parameter space**. From CUDA 12.1 on, a kernel for compute capability 7.0 (Volta) or newer may take up to **32,764 bytes** of parameters; older toolkits allowed 4,096 bytes. G# builds with the CUDA Toolkit 13.0 or newer, whose oldest target is compute capability 7.5, so every build G# supports has the 32,764-byte limit, whatever `GSharpTargetArchitectures` lists.

A kernel above the limit cannot be compiled: nvcc stops with `Formal parameter space overflowed (<n> bytes required, max 32764 bytes allowed)`. GSH0064 reports it at the kernel, before nvcc runs, as an error. A kernel within the limit gets no diagnostic: passing a struct of a few kilobytes by value is valid and efficient, since the threads of a warp read the parameter space through the constant cache.

Device functions (`[GpuDeviceFunction]`) pass their parameters in registers or on the stack and have no such limit.

## Cause

The emitted `__global__` parameter list, computed in declaration order with C++ alignment, takes more than 32,764 bytes:

- `ref` / `out` / `in` parameters: an 8-byte pointer (alignment 8).
- Array-like parameters (`T[]`, `Span<T>`, `Memory<T>`, `ArraySegment<T>`, `ImmutableArray<T>`, ...): the `GSharpArray<T>` header of a device pointer, the length and a flags word (16 bytes, alignment 8).
- Value parameters: the CUDA layout of the type, nested field padding included.
- Each parameter is aligned to its alignment before its size is added.
- Then the parameters G# appends, in this order: the pointer to the result buffer of a kernel that returns a value (8 bytes), the scratch pointer of a grid aggregate of `AsParallel()` (8 bytes), and the 4-byte epoch of the launch, which every CUDA kernel takes.

The check counts the CUDA parameter list also in a CPU dialect build, since the kernel is meant for the GPU.

## How to Fix

Pass large data through a one-element array (`T[]`), a `Span<T>`, or a device buffer instead of by value.

## Examples

### Code with Error (Before)

```csharp
// Execution Context: G# Kernel (GPU)
[InlineArray(10240)]
public struct Block40K // 40,960 bytes
{
    private int _element;
}

public static partial class Kernels
{
    [GpuKernel]
    // Error GSH0064: 16 (array header) + 40,960 + 4 (launch epoch) = 40,980 bytes (> 32,764 bytes)
    public static void OversizedKernel(int[] data, Block40K config)
    {
        data[ThreadIndex.X] = config[0];
    }
}
```

### Corrected Code (After)

```csharp
// Execution Context: G# Kernel (GPU)
public static partial class Kernels
{
    [GpuKernel]
    // Correct: the array passes only its 16-byte header (device pointer, length, flags)
    public static void FixedKernel(int[] data, Block40K[] config)
    {
        data[ThreadIndex.X] = config[0][0];
    }
}
```
