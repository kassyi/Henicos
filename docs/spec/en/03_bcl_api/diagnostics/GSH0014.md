# GSH0014: Large struct passed by value

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0014 |
| **Category** | GSharpTranspiler |
| **Severity** | Warning |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### Constant Memory Exhaustion and Parameter Register Overhead
When a host program launches a CUDA kernel, all parameters are copied into a specialized hardware cache called **Constant Memory** (Parameter Space), which is limited to between 4 KB and 64 KB across different architectures.

1. **Parameter Cache Thrashing**: Passing structs $\ge 32$ bytes by value consumes parameter space rapidly.
2. **Excessive Register Copy Instructions**: Device-side entry points must copy every byte of value-passed structs into thread registers, consuming register file space and increasing register pressure (which can trigger spilling to slow local memory).
Passing by reference (`ref`) passes a lightweight 64-bit pointer instead, completely eliminating struct copy overhead.

## Cause

A custom struct containing 32 or more bytes of fields was passed as a kernel parameter by value.

## How to Fix

Pass the struct by reference using the `ref` keyword, or pass an array pointer (`T[]` or `T*`).

## Examples

### Code with Warning / Error (Before)

```csharp
// Execution Context: G# Kernel (GPU)
// Struct size = 10 * 4 = 40 bytes
public struct PhysicsParams
{
    public float M1, M2, M3, M4, M5, M6, M7, M8, M9, M10;
}

public static class Kernels
{
    [GpuKernel]
    // Warning GSH0014: Large struct passed by value consumes constant memory parameter space
    public static void BadKernel(PhysicsParams p) { }
}
```

### Corrected Code (After)

```csharp
// Execution Context: G# Kernel (GPU)
public static class Kernels
{
    [GpuKernel]
    // Correct: Passing by ref transfers only an 8-byte pointer, saving parameter memory
    public static void GoodKernel(ref PhysicsParams p) { }
}
```
