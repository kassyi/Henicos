# GSH0080: Struct array or returned struct is converted element by element

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0080 |
| **Category** | GSharpTranspiler |
| **Severity** | Warning |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

An array of structs whose host and device layouts are the same is pinned and copied to the device in one transfer. When the layouts differ, the bytes cannot be copied as they are: on CUDA, `Vector2` and `Float2` are 8-byte aligned and `Vector4` and `Float4` 16-byte aligned, while .NET aligns them to 4 bytes, so a vector field after a `float` moves to a later offset on the device. The runtime may also reorder the fields of a `LayoutKind.Auto` struct or of a struct that holds an array.

A difference in alignment alone does not count: when every field is at the same offset and the struct has the same size on both sides, the bytes are the same and the array is copied as one block.

In that case the launcher converts each element into a temporary array of the device layout (the `AotContexts` shadow, rented from `ArrayPool<byte>`), copies that array in one transfer, and converts each element back after the kernel. The result is correct, but every launch pays for the conversion on the host. The same applies to an `[InlineArray]` whose element layout differs, inside a struct passed to a kernel.

Both dialects report this warning. The CPU launcher converts the elements into the same shadow array in host memory and passes it to the kernel in place; the CUDA launcher copies it to the device. The CPU dialect also converts a struct whose array fields make its layout differ; it pins those arrays instead of copying them.

## Cause

A `[GpuKernel]` parameter is an array (`T[]`, `Span<T>`, `Memory<T>`, `ArraySegment<T>`, `ImmutableArray<T>` ...) of a struct whose host and device layouts differ, a struct parameter contains an `[InlineArray]` of such a struct, or the kernel returns such a struct: the returned values come back as an array with one element per thread, which the launcher reads in the device layout and converts back element by element. The message names the struct and the first difference (`field 'V' is at offset 4 on the host and 8 on the device`).

## How to Fix

- Order the fields of the array element or the returned struct from the largest alignment to the smallest, so that every field lands at the same offset on both sides and the struct has the same size: `{ Float4 W; Float2 V; float A; float B; }` instead of `{ float A; Float2 V; float B; Float4 W; }`. This also makes the struct smaller on the device.
- Remove `LayoutKind.Auto` from structs that are passed in arrays or returned from a kernel, and avoid array fields in them ([GSH0081](GSH0081.md)).
- If the conversion is acceptable, suppress the warning with `#pragma warning disable GSH0080` or in `.editorconfig`.

## Examples

### Code with Warning (Before)

```csharp
// Execution Context: G# Kernel (GPU)
public struct Particle
{
    public float Mass;
    public Float2 Velocity; // offset 4 on the host, 8 on CUDA
    public float Charge;
}

public static partial class Kernels
{
    [GpuKernel]
    public static void Step(Particle[] particles) // ⚠️ GSH0080: field 'Velocity' is at offset 4 on the host and 8 on the device
    {
        particles[ThreadIndex.X].Mass *= 0.5f;
    }
}
```

### Corrected Code (After)

```csharp
// Execution Context: G# Kernel (GPU)
public struct Particle
{
    public Float2 Velocity; // offset 0 on both sides
    public float Mass;      // offset 8
    public float Charge;    // offset 12; 16 bytes on both sides
}

public static partial class Kernels
{
    [GpuKernel]
    public static void Step(Particle[] particles) // ✅ copied as one block
    {
        particles[ThreadIndex.X].Mass *= 0.5f;
    }
}
```
