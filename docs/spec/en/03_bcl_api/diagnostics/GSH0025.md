# GSH0025: Unguarded multi-allocation

## Details

| Property               | Value            |
| :--------------------- | :--------------- |
| **Diagnostic ID**      | GSH0025          |
| **Category**           | GSharpTranspiler |
| **Severity**           | Error            |
| **Enabled by Default** | Yes              |

## Why This Rule Exists (Architectural Context)

### Partial Construction Hazards and Constructor Leaks

If a constructor allocates Resource A and then attempts to allocate Resource B, and Resource B throws an exception (e.g. `OutOfMemoryException` or CUDA error), the constructor aborts. Because the object was never fully constructed, its finalizer and `Dispose()` methods will never be called, causing Resource A to leak permanently.

## Cause

A constructor performed multiple disposable resource allocations without guarding subsequent allocations in a `try/catch` block.

## How to Fix

Wrap subsequent allocations in `try/catch` and clean up earlier allocations if an error occurs.

## Examples

### Code with Warning / Error (Before)

```csharp
// Execution Context: Host (CPU)
public MultiBufferManager(int size1, int size2)
{
    // ❌ Error GSH0025: If _b2 allocation fails, _b1 is permanently leaked
    _b1 = new GpuBuffer<int>(size1);
    _b2 = new GpuBuffer<int>(size2);
}
```

### Corrected Code (After)

```csharp
// Execution Context: Host (CPU)
public MultiBufferManager(int size1, int size2)
{
    _b1 = new GpuBuffer<int>(size1);
    // ✅ Correct: Wrap with try-catch and call Dispose() on the earlier allocation if an error occurs
    try
    {
        _b2 = new GpuBuffer<int>(size2);
    }
    catch
    {
        _b1.Dispose();
        throw;
    }
}
```
