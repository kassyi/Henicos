# GSH0041

## Stack pointers cannot be held across barrier synchronization

| | |
| :--- | :--- |
| **Category** | GSharpTranspiler |
| **Severity** | Error |

## Cause

A pointer to a local variable (using the `&` operator) or a pointer obtained via `stackalloc` was held across a `Gpu.SyncThreads()` barrier.

## Rule Description

To emulate GPU thread execution on the host CPU, the G# compiler transforms kernel methods into Bulk Synchronous Parallel (BSP) state machines. When a state machine suspends at a barrier, it physically returns from the method, destroying the C# call stack.
If a pointer points to memory allocated on the stack, that memory is discarded. When the state machine resumes, the pointer becomes a dangling pointer, leading to Access Violations.

## How to Fix

Do not allocate memory on the stack if it needs to persist across barriers. Instead, use block-scoped `SharedMemory<T>` or global memory pointers.

## Examples

### Code with Warning / Error (Before)

```csharp
[GpuKernel]
public unsafe static void Kernel()
{
    int* localArr = stackalloc int[10];
    
    // ❌ Error GSH0041: Stack pointer cannot cross barrier
    Gpu.SyncThreads(); 
    
    localArr[0] = 1; 
}
```

### Corrected Code (After)

```csharp
[GpuKernel]
public unsafe static void Kernel(int* globalMem)
{
    var shared = new SharedMemory<int>(10);
    
    // ✅ Correct: SharedMemory is managed by the emulation context
    Gpu.SyncThreads();
    
    globalMem[0] = 1;
    shared[0] = 1;
}
```
