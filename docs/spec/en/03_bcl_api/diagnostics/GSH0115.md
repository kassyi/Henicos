# GSH0115: The managed CPU path cannot call a device function that waits at a barrier from here

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0115 |
| **Category** | GSharpCompiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

On the C++ dialect, G# can run a kernel on the managed fallback, in C#. A device function that waits at a barrier
(`Gpu.SyncThreads()`, directly or through another function) runs there as a state machine: its locals and parameters
live in a frame class, which G# generates into a `partial` declaration of the function's class, and the kernel's context
holds the frame of every such call.

The frame names the types of the locals it keeps, so it can be no more visible than they are. When a local has a private
nested type of the function's class, the frame is a private class of that class: C# lets only that class and the types
nested in it name the frame. A kernel of another class cannot hold it. A file-local type (`file struct`) cannot be named
from the generated file at all, so no frame is generated for a function that keeps one.

G# reports such a call instead of generating a context that names a frame it cannot reach, which would fail with C#
errors in generated code. The managed state machine of the kernel then throws `NotSupportedException`. The CUDA dialect
and the native C++ path do not use the frames and are not affected.

## Cause

On the C++ dialect, a kernel calls a device function that waits at a barrier, and the function's frame is out of the
kernel's reach. The message names the function and the reason:

- **Its frame holds a type that only its class can name**: a local, parameter or return value of the function has a
  private nested type of the function's class, and the kernel is declared outside that class.
- **It calls a function that its class cannot call**: the function calls such a function in turn, so it has no frame
  either; the message names the function it calls and that function's reason.
- **Its frame would hold a file-local type**: a local, parameter or return value of the function has a file-local type.

## How to Fix

Declare the kernel in the class that declares the private type (or in a type nested in it), or make the type `internal`.
Declare a file-local type without the `file` modifier.

## Examples

### Code with Error (Before)

```csharp
// Execution Context: GPU (C++ dialect)
public static partial class Steps
{
    private struct State
    {
        public int X;
    }

    [GpuDeviceFunction]
    internal static int Step(int[] data)
    {
        var state = new State { X = data[ThreadIndex.X] * 2 };
        Gpu.SyncThreads();
        return state.X;
    }
}

public static partial class Kernels
{
    [GpuKernel]
    public static void StepKernel(int[] data) => data[ThreadIndex.X] = Steps.Step(data); // error GSH0115
}
```

### Corrected Code (After)

```csharp
// Execution Context: GPU (C++ dialect)
public static partial class Steps
{
    private struct State
    {
        public int X;
    }

    [GpuDeviceFunction]
    internal static int Step(int[] data)
    {
        var state = new State { X = data[ThreadIndex.X] * 2 };
        Gpu.SyncThreads();
        return state.X;
    }

    // The kernel is declared in the class whose private type the frame holds
    [GpuKernel]
    public static void StepKernel(int[] data) => data[ThreadIndex.X] = Step(data);
}
```
