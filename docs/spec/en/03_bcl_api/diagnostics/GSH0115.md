# GSH0115: The managed CPU path cannot run a device function that waits at a barrier

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0115 |
| **Category** | GSharpCompiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

On the C++ dialect, G# can run a kernel on the managed fallback, in C#. A device function that waits at a barrier
(`Gpu.SyncThreads()`, directly or through another function) runs there as a state machine: its locals and parameters
live in a frame, which G# generates into a `partial` declaration of the function's class, and the kernel's context
holds the frame of every such call.

The frame names the types of the locals it keeps. A file-local type (`file struct`) can be named only in the file that
declares it, and G# generates the frame into a file of its own, so no frame is generated for a function that keeps one.
A kernel that calls such a function, directly or through another device function, has no frame to hold.

A private nested type is not a problem: the frame is then a private class of the function's class, and a kernel or
device function of another class holds it as an `object` and runs it through members that G# generates beside the
function.

G# reports such a call instead of generating a context that names a frame that does not exist, which would fail with C#
errors in generated code. The managed state machine of the kernel then throws `NotSupportedException`. The CUDA dialect
and the native C++ path do not use the frames and are not affected.

## Cause

On the C++ dialect, a kernel calls a device function that waits at a barrier and has no frame. The message names the
function and the reason:

- **Its frame would hold a file-local type**: a local, parameter or return value of the function has a file-local type.
- **It calls a function whose frame cannot be generated**: the function calls such a function in turn, so it has no
  frame either; the message names the function it calls and that function's reason.
- **It has no entries for callers outside its class**: its frame holds a private nested type of its class, and the
  function is neither `public` nor `internal` (for example `protected`), so G# generates no members through which another
  class could run it.

## How to Fix

Declare the file-local type without the `file` modifier (a `private` or `internal` type works on every path). Make a
function whose frame holds a private type `internal` or `public`.

## Examples

### Code with Error (Before)

```csharp
// Execution Context: GPU (C++ dialect)
file struct State
{
    public int X;
}

public static partial class Steps
{
    [GpuDeviceFunction]
    internal static int Step(int[] data)
    {
        var state = new State { X = data[ThreadIndex.X] * 2 };
        Gpu.SyncThreads();
        return state.X;
    }

    [GpuKernel]
    public static void StepKernel(int[] data) => data[ThreadIndex.X] = Step(data); // error GSH0115
}
```

### Corrected Code (After)

```csharp
// Execution Context: GPU (C++ dialect)
public static partial class Steps
{
    // A private nested type instead of a file-local one: the generated frame can name it
    private struct State
    {
        public int X;
    }

    [GpuDeviceFunction]
    internal static int Step(int[] data)
    {
        var state = new State { X = data[ThreadIndex.X] * 2 };
        Gpu.SyncThreads();
        return state.X;
    }

    [GpuKernel]
    public static void StepKernel(int[] data) => data[ThreadIndex.X] = Step(data);
}
```
