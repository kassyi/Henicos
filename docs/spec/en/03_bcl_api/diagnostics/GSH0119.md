# GSH0119: A file-local type cannot be named by the managed copy that G# generates

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0119 |
| **Category** | GSharpCompiler |
| **Severity** | Warning |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

A kernel can run on the CPU dialect in three ways: as the user's C# method (`KernelExecution.CSharp`), through the native
module, and on the managed path, which runs the kernel thread by thread when the native module is not used. The C#
execution and the native module never copy C#, and neither does the CUDA dialect, so a file-local type (`file struct`,
`file class`) in a body is no problem there.

The managed path calls the user's own method wherever it can: a kernel or device function that does not suspend and holds
no construct that only the managed path rewrites runs as the user wrote it, and may name a file-local type. It writes a
copy of the body into a generated file when the body

- suspends (it waits at a barrier or a warp exchange, directly or through a call), so that the copy is a state machine,
- holds a construct whose meaning on the managed path comes from code that G# writes (an operator macro, a `float` or
  `double` StackLinq `Sum`, `Gpu.InlinePtx`, or an integer `/` or `%` that may divide `int.MinValue` by `-1`: the GPU
  gives `int.MinValue`, C# throws, and the managed path follows the GPU; a division that provably cannot reach that
  case, such as one by a constant other than `-1`, keeps the C# operator and is not such a construct), or
- is a kernel that reaches something the C# execution cannot run one GPU thread at a time, or a kernel or function that
  calls a function that needs such a copy.

C# has no way to name a file-local type from another file, so a copy that names one cannot be written. G# reports each
such name, and a kernel or function whose copy needs such a body, and does not write the copy. The managed launch of
the kernel that needs it throws `NotSupportedException` with the type and the reason; its C# execution, its native
module and its CUDA launch are generated as for any kernel. The exception is thrown by the managed launch only: a
kernel that takes a `ref struct` parameter and runs as the user's method has no managed launch of its own, and its
default launch is unaffected. The name may be the type itself, a static member of it, an
extension method declared in it (also an extension `Deconstruct` of a deconstruction), or a type nested in it;
`nameof(...)` is written as its string and is not reported.

## Cause

A body that the managed path must copy names a file-local type, or a function whose copy it needs does.

## How to Fix

Declare the type without `file`, for example as a `private` type nested in the class that uses it.

## Examples

### Code with a Warning (Before)

```csharp
file struct LocalValue
{
    public int A;
}

public static partial class LocalKernels
{
    [GpuKernel]
    public static void Run(int[] data)
    {
        LocalValue v = new LocalValue { A = 1 };   // GSH0119 (CPU dialect), at both names of LocalValue
        Gpu.SyncThreads();                         // the kernel suspends: its managed copy is a state machine
        data[ThreadIndex.X] = v.A;
    }
}
```

### Corrected Code (After)

```csharp
public static partial class LocalKernels
{
    private struct LocalValue
    {
        public int A;
    }

    [GpuKernel]
    public static void Run(int[] data)
    {
        LocalValue v = new LocalValue { A = 1 };   // OK
        Gpu.SyncThreads();
        data[ThreadIndex.X] = v.A;
    }
}
```
