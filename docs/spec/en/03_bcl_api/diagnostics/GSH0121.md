# GSH0121

## A goto reaches the inner label of chained labels from another state

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0121 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

> [!NOTE]
> GSH0121 is temporary. A later version of G# lets such a label start a state of its own, and the jump then builds;
> the diagnostic will be deprecated then ([#2121](https://github.com/kassyi/Henicos/issues/2121)).

## Cause

A `goto` in a kernel or in a `[GpuDeviceFunction]` that the CPU paths split into states jumps to a label written right
after another label, such as `second` in `first: second: v += 1;`, from another state than the one the label is in.
It is reported where the managed state machine of the method is built: on a project that builds the CPU paths (any
dialect but `Cuda`), and for a `[GpuDeviceFunction]` of a `Cuda` project that exports its device code
(`GSharpExportDeviceCode`, on by default), whose consumers on the CPU paths run that state machine.

## Rule Description

The CPU paths (native C++ and managed) run a method that holds a barrier, a warp collective or a call that suspends as
a state machine. Each stretch between two such points is a state, and a label that a `goto` from another state reaches
starts a state of its own, so that the jump becomes a jump between states. Only the first label of a statement can start
a state. A label written right after it names the same statement but stays an ordinary label inside its state, so a
`goto` to it from another state would jump into the middle of another state, which the generated code cannot do. G#
reports the jump instead of failing the build with an error in generated code.

A `goto` to such a label from the same state, and a `goto` to the first label, are not reported. A `goto` across a
barrier or a call that suspends is reported as [GSH0040](GSH0040.md) instead, so the states that GSH0121 is about are
split by a warp collective, a grid sync, or a label that starts a state: one that another `goto` reaches, or one that
G# adds, such as the end of a region where the lanes of a warp meet again. A `Cuda` kernel is not reported: the GPU
runs it as written.

## How to Fix

- Jump to the first label of the statement (`goto first;`): every label of the chain names the same statement.
- Or write an empty statement right before the label, so that it starts a statement of its own:
  `first: ; second: v += 1;`.

## Examples

### Code with Error (Before)

```csharp
[GpuKernel]
public static void ChainedShuffleBackInnerKernel(int[] result)
{
    int t = ThreadIndex.X;
    int n = 0;
    int v = t;
first:
second:
    v += 1;
    v = Warp.ShuffleXorSync(0xFFFFFFFFu, v, 1);
    if (n++ < 1)
    {
        goto second; // Error GSH0121: 'second' is written right after 'first', across the shuffle
    }

    result[t] = v;
}
```

### Corrected Code (After)

```csharp
[GpuKernel]
public static void SplitShuffleBackInnerKernel(int[] result)
{
    int t = ThreadIndex.X;
    int n = 0;
    int v = t;
first:
    ;
second:
    v += 1;
    v = Warp.ShuffleXorSync(0xFFFFFFFFu, v, 1);
    if (n++ < 1)
    {
        goto second; // OK: 'second' has a statement of its own and starts a state
    }

    result[t] = v;
}
```
