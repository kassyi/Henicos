# GSH0082: Struct cannot be passed to a CPU kernel yet

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0082 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

The CUDA launcher converts a struct whose host and device layouts differ through its native shadow struct (`AotContexts`), element by element for an array ([GSH0080](GSH0080.md)). The CPU launcher does not convert yet: it passes a struct by value through the .NET marshaller, a `ref` struct as a pointer to the managed value, and an array as a pointer to its managed elements, all in the host layout. The C++ kernel reads the device layout, so a struct whose layouts differ is read with the wrong bytes, and a pointer read from the wrong offset can crash the process.

On the CPU dialect the layouts differ when the runtime may reorder the fields on the host: a `LayoutKind.Auto` struct, or a struct that holds an array field (directly, in a nested struct or in an `[InlineArray]` element). The vector types are 4-byte aligned on both sides, so they do not cause this diagnostic.

## Cause

A `[GpuKernel]` parameter of a project with the CPU dialect is such a struct, by value, by `ref` or as an array-like type.

## How to Fix

- Remove `LayoutKind.Auto` from the struct.
- Replace an array field with a separate array parameter and an index or offset in the struct.
- Build for the CUDA dialect, which converts the struct.

## Remarks

This is a limitation of the current CPU launcher, not of the struct: the CPU launcher copies structs in the host layout. This error is removed when the CPU launcher converts structs as the CUDA launcher does.

GSH0082 covers only the layouts that the layout model sees as different. It does not detect a struct passed by value to a CPU kernel whose bytes the .NET marshaller changes on the way: the marshaller passes a `bool` field as a 4-byte value and a `char` field as a 1-byte value (for example `{ bool F; bool G; int X; }` or a struct with `bool` and `char` fields), while the C++ kernel reads 1 and 2 bytes. Such a struct is still read with the wrong bytes on the CPU dialect without a diagnostic; pass it in an array instead, which is copied without the marshaller.

## Examples

### Code with Error (Before)

```csharp
// Execution Context: G# Kernel (CPU dialect)
public struct Bag
{
    public int Count;
    public int[] Items;
}

public static partial class Kernels
{
    [GpuKernel]
    public static void Read(Bag[] bags, int[] counts) // ❌ GSH0082: field 'Items' is an array
    {
        counts[ThreadIndex.X] = bags[ThreadIndex.X].Count;
    }
}
```

### Corrected Code (After)

```csharp
// Execution Context: G# Kernel (CPU dialect)
public struct Bag
{
    public int Start;
    public int Count;
}

public static partial class Kernels
{
    [GpuKernel]
    public static void Read(Bag[] bags, int[] items, int[] counts) // ✅
    {
        counts[ThreadIndex.X] = bags[ThreadIndex.X].Count;
    }
}
```
