# GSH0109: A method without a device implementation is called from GPU code

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0109 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

G# does not compile the IL of the methods your kernels call. A call in GPU code works only when the call has a definition on the device:

- a `[GpuDeviceFunction]` method, of your project or of a referenced assembly;
- a native function that the dialect maps the method to: a `[CudaIntrinsic]`, `[CudaImport]` or operator macro method, a member of `System.Math` or `System.MathF` that the dialect lists (see [BCL Mappings](../02_bcl_mappings.md#103-systemmath-and-systemmathf)), or a `[BclIntrinsicMap]` mapping such as the members of `Interlocked` and `BitOperations`;
- a construct that G# writes itself: the `Gpu` macros, StackLinq, the members of `Span<T>`, arrays and `MemoryExtensions` that G# supports, and `Nullable<T>.GetValueOrDefault`.

Any other method of another assembly has no definition in the generated device code. Without this check the C# name of the method would be written into the C++ output, and the native build would fail with an undefined identifier and no location in your source. The check is a closed list, as in other GPU compilers for .NET: a method is accepted because G# knows how to emit it, not because nothing rejects it.

A method of your own project without `[GpuDeviceFunction]` is reported as [GSH0107](GSH0107.md) instead: there the fix is to mark the method.

## Cause

A `[GpuKernel]` or `[GpuDeviceFunction]` method calls, or names as a method group, a method of another assembly that the project's dialect (`GSharpTargetDialect`) does not implement. The mapping is per overload: `Math.Max(int, int)` is mapped, `Math.Max(long, long)` is not. The generic math members of the numeric types (`int.Max`, `float.Clamp`, `int.Abs`) are separate methods from the `Math` members, and only the ones the dialect lists are mapped.

A `Gpu` macro that takes its body as a lambda (`Gpu.SingleThread`, `Gpu.ForUnroll`, `Gpu.GridStrideLoop`) is reported as well when the body is passed as a method group or a delegate (`Gpu.SyncGrid(body)` reports it as [GSH0003](GSH0003.md)).

The message names the method with its parameter types and the dialect. When the dialect implements a method that does the same, or other overloads of the same name, the message lists them.

## How to Fix

Call a method that the dialect implements: the `Math` member with the same parameters (`Math.Max(a, b)` for `int.Max(a, b)`), a mapped overload (convert the operands), or a `[GpuDeviceFunction]` method that you write. Pass the body of a `Gpu` macro as a lambda.

## Examples

### Code with Error (Before)

```csharp
[GpuKernel]
public static void Clip(float[] f, int[] i, long[] l)
{
    int t = ThreadIndex.X;
    f[t] = float.Clamp(f[t], 0f, 1f); // GSH0109: use Math.Clamp(float, float, float) instead
    i[t] = int.Max(i[t], 3);          // GSH0109: use Math.Max(int, int) instead
    l[t] = Math.Max(l[t], 3L);        // GSH0109: Math.Max(long, long) is not mapped
    Gpu.SingleThread(Report);         // GSH0109: the body of the macro must be a lambda
}

[GpuDeviceFunction]
public static void Report() { }
```

### Corrected Code (After)

```csharp
[GpuKernel]
public static void Clip(float[] f, int[] i, long[] l)
{
    int t = ThreadIndex.X;
    f[t] = Math.Clamp(f[t], 0f, 1f);
    i[t] = Math.Max(i[t], 3);
    l[t] = l[t] > 3L ? l[t] : 3L;
    Gpu.SingleThread(() => Report());
}

[GpuDeviceFunction]
public static void Report() { }
```
