# GSH0084

## Barrier after an exit that only some threads take

|  |  |
| :--- | :--- |
| **Category** | GSharpTranspiler |
| **Severity** | Warning |

## Cause

In a `[GpuKernel]`, a condition that may differ between the threads of a block sends some threads out of the kernel before a `Gpu.SyncThreads()` (a `Gpu.SyncGrid()`: between the threads of the grid) that the other threads still reach, and the threads that leave reach no other barrier on their way out. Examples:

- An early `return` before a barrier: `if (ThreadIndex.X >= n) return; Gpu.SyncThreads();`.
- A barrier at the end of a branch, with nothing after it in the kernel: `if (ThreadIndex.X < 16) { Gpu.SyncThreads(); }`.
- A `break` out of a loop whose body holds a barrier, or a loop whose number of iterations differs between threads (`for (int i = ThreadIndex.X; i < n; i += BlockDimension.X)`), with no barrier after the loop.
- A call to a `[GpuDeviceFunction]` that lets some threads leave early before one of its barriers, with no barrier after the call.

The warning is reported at the condition (the switch expression for a `case`), or at the call, with the first barrier it skips as an additional location. A device function is not reported by itself: where it is called decides whether the threads that leave meet the others again (then the call is [GSH0037](GSH0037.md) or [GSH0083](GSH0083.md)) or leave the kernel (then this warning).

When the threads that skip the barrier meet the others at a later barrier, or at the same barrier in the next iteration of a loop (`continue`), it is [GSH0083](GSH0083.md) instead.

## Rule Description

The CPU dialects end a thread that returns from the kernel and keep running the others through the barrier, so the result there is what the remaining threads compute. The CUDA documentation does not state what `__syncthreads()` does when some threads of the block have already exited, so the kernel relies on behavior that is not specified. A bounds guard such as `if (ThreadIndex.X >= n) return;` is common and correct whenever every launch has exactly `n` threads, which the analyzer cannot know, so this is a warning.

## How to Fix

- Move the exit after the barrier: let every thread reach the barrier, and skip only the work (`if (ThreadIndex.X < n) { ... }` around the work, with the barrier outside).
- Or launch exactly as many threads as the guard allows, and remove the guard.

## Examples

```csharp
[GpuKernel]
public static void Kernel(int[] data, int n)
{
    int tid = ThreadIndex.X;
    if (tid >= n)
    {
        return; // GSH0084: these threads never reach the barrier below
    }

    Gpu.SyncThreads();
    data[tid] += 1;
}
```

Corrected:

```csharp
[GpuKernel]
public static void Kernel(int[] data, int n)
{
    int tid = ThreadIndex.X;
    Gpu.SyncThreads();
    if (tid < n)
    {
        data[tid] += 1;
    }
}
```
