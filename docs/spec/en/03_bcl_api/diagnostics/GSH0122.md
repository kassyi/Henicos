# GSH0122: Math.Clamp is called with a constant min greater than its constant max

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0122 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

`Math.Clamp(value, min, max)` throws `ArgumentException` in C# when `min` is greater than `max`. CUDA and the native CPU
build have no exception to throw and would return a value instead, which C# never produces.

G# treats a result that C# defines as a failure, and a form that is certain to fail at compile time, as an error
([Semantics](../../01_language/06_semantics.md)). When both bounds are constants (literals, `const` fields and locals,
constant expressions), the call fails whenever it runs, so it is reported at the call. Bounds known only at run time are
not reported here.

`NaN` bounds and `-0.0` against `0.0` are not reported: .NET does not throw for them.

## How to Fix

Swap the bounds, as the message suggests.

## Example

```csharp
[GpuKernel]
public static void ClampKernel(int[] v)
{
    int t = ThreadIndex.X;

    // Incorrect: GSH0122, min 10 is greater than max 5
    v[t] = Math.Clamp(v[t], 10, 5);

    // Correct
    v[t] = Math.Clamp(v[t], 5, 10);
}
```
