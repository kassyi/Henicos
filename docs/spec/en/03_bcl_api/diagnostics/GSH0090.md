# GSH0090: Device code of two assemblies has the same C++ name

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0090 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

The C++ name of a device function or struct follows its C# path (`__gsharp_fn_<namespace>__<type>__<name>`), without the assembly name, so that the names stay readable and the symbol files decode them back to C#. Two assemblies that declare the same path, which .NET allows and C# tells apart with `extern alias`, give one C++ name to two definitions. The consumer's native module cannot hold both.

## Cause

GPU code uses a device function or struct of a referenced assembly, and another referenced assembly (or the compilation itself) declares the same namespace, type and member. The same applies to what the recorded text calls in turn (an internal helper of the library, for example); the use of the library function is then reported with the name of the helper.

## How to Fix

Rename the namespace or the type in one of the assemblies.

## Example

```csharp
// LibA and LibB both declare XasmLib.LibMath.Twice
extern alias LibA;

public static partial class Kernels
{
    [GpuKernel]
    public static void Run(int[] data)
    {
        data[ThreadIndex.X] = LibA::XasmLib.LibMath.Twice(data[ThreadIndex.X]); // Incorrect: GSH0090
    }
}
```
