# SLQ0001: Excessive StackLinq chain depth

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | SLQ0001 |
| **Category** | StackLinqPerformance |
| **Severity** | Warning |
| **Enabled by Default** | Yes |

---

## Why This Rule Exists (Architectural Context)

`Kassyi.ZeroAlloc.Linq` (`StackLinq`) relies on nesting `ref struct` enumerators to avoid heap allocations. While this eliminates garbage collection and permits loop fusion:

1. **Stack Frame Growth on CPU**:
   Each chained enumerator (`WhereEnumerator`, `SelectEnumerator`, etc.) adds internal state fields (`_source`, `_index`, `_predicate`) directly to the method's stack frame. An overly deep chain can inflate stack memory and reduce cache efficiency.
2. **Register Pressure on GPU (CUDA)**:
   In GPU Streaming Multiprocessors (SMs), each thread has a fixed, hardware-limited register pool (typically 32 to 64 registers). Deeply nested enumerators force the CUDA compiler to accumulate intermediate variables across the pipeline. When the register limit is exceeded, the compiler triggers **Register Spilling** into slow Local Memory (VRAM/L1 stack backing), degrading performance up to ~4.8x compared to flat loops.

To maintain optimal performance across both CPU and GPU execution, `SLQ0001` warns when the number of chained operations exceeds the safe threshold (default: 6 intermediate operations).

---

## Cause

A single fluent StackLinq query chain contains more than 6 chained intermediate operators (e.g. chaining `Where`, `Select`, `Skip`, `Take`, `SkipWhile`, `TakeWhile`, etc. consecutively).

---

## How to Fix

1. **Break into Intermediate Loops**:
   If processing is inherently complex, consider breaking the computation into discrete stages or using an explicit loop for non-trivial transformations.
2. **Combine Predicates and Projections**:
   Instead of chaining consecutive `.Where(x => ...).Where(y => ...)`, combine them into a single condition `.Where(x => cond1 && cond2)`.
3. **Wait for Compiler Loop Fusion (#309)**:
   For GPU kernels where deeply nested chains are unavoidable, future releases of the GSharp Transpiler will introduce AST Loop Fusion (Deforestation) to flatten chains automatically.

---

## Examples

### Code with Warning (Before)

```csharp
// ❌ Warning SLQ0001: StackLinq chain depth exceeds recommended limit (7 operations)
var result = data.AsStackEnumerable()
                 .Where(x => x > 0)
                 .Select(x => x * 2)
                 .Skip(5)
                 .Take(100)
                 .Where(x => x % 4 == 0)
                 .Select(x => x + 1)
                 .SkipLast(2)
                 .Sum();
```

### Preferred Code (After)

```csharp
// ✅ Combine conditions and eliminate redundant intermediate projections
var result = data.AsStackEnumerable()
                 .Skip(5)
                 .Take(100)
                 .SkipLast(2)
                 .Where(x => x > 0 && (x * 2) % 4 == 0)
                 .Select(x => (x * 2) + 1)
                 .Sum();
```
