# GSH0018: GPU intrinsic called from host

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0018 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### Execution Context Segregation and Hardware Register Isolation
APIs in `Kassyi.GSharp.Core` such as `ThreadIndex.X`, `BlockDimension.Y`, `Gpu.SyncThreads()`, and `Warp.ShuffleXorSync()` are intrinsic markers designed to be intercepted by the Roslyn transpiler and emitted as native PTX hardware instructions (e.g. `%tid.x`, `bar.sync`, `shfl.sync.bfly`).

These instructions map to physical GPU registers that do not exist on the CPU host. If executed on the host, the real C# member throws `GpuOnlyException` (inside a managed launch the managed CPU path gives it its value instead). `GSH0018` catches this error at compile-time to prevent runtime CPU crashes.

## Cause

Code that is not in a method decorated with `[GpuKernel]` or `[GpuDeviceFunction]` (or in a lambda or local function inside one) uses a GPU-only member of `Kassyi.GSharp.Core`:

- calls it (`Gpu.SyncThreads()`, `Warp.LaneId()`, `Gpu.AtomicAdd(ref x, 1)`),
- reads it (`ThreadIndex.X`, `BlockIndex.Y`, `BlockDimension.Z`, `GridDimension.X`, the properties of `Dim3`, the indexer of `SharedMemory<T>`),
- or names it as a method group (`Action sync = Gpu.SyncThreads;`, `&Gpu.SyncThreads`).

The GPU-only members are:

| Members | On the host |
| :--- | :--- |
| Members marked `[CudaIntrinsic]`: `Gpu.SyncThreads`, `Gpu.SyncGrid(GridSyncMode)`, and every intrinsic generated from the native API definitions (`Gpu.Atomic*`, `Gpu.PopCount`, `Gpu.Unsafe.Malloc`, `Warp.*`, `Wmma.*`, ...) | Throw `GpuOnlyException` outside a managed launch |
| The properties of `ThreadIndex`, `BlockIndex`, `BlockDimension` and `GridDimension` (types marked `[CudaIntrinsicPattern]`) | Throw `GpuOnlyException` outside a managed launch |
| The `Gpu` macros `ForUnroll`, `GridStrideLoop`, `SingleThread`, `SyncGrid(Action)`, `Constant` and `InlinePtx` | Throw `GpuOnlyException` outside a managed launch |
| The indexer of `SharedMemory<T>` | Throws `GpuOnlyException` outside a managed launch; its constructors give an empty buffer and are not reported |
| The properties of `Dim3` | Always throw `GpuOnlyException` |

`Gpu.NotNull` and `Gpu.Hint.Unroll` work on the host and are not reported.

The rule also analyzes generated code, such as the output of another source generator or a file marked `// <auto-generated/>`. It skips the output of the G# generator itself, whose managed kernel bodies use these members inside a managed launch. It does not report a use that does not run: the argument of `nameof`, or the arguments of a call that C# removes (a `[Conditional]` method whose symbol is not defined).

## How to Fix

Move the GPU intrinsic call into a kernel or device function, or remove it from host CPU code. To run a kernel, launch it with its generated `Launch{Kernel}` method.

## Examples

### Code with Warning / Error (Before)

```csharp
// Execution Context: Host (CPU)
public class Program
{
    public static void Main()
    {
        // ❌ Error GSH0018: The GPU intrinsic 'Gpu.SyncThreads' cannot be called from a host method
        Gpu.SyncThreads();

        // ❌ Error GSH0018: The GPU intrinsic 'ThreadIndex.X' cannot be called from a host method
        int index = ThreadIndex.X;
    }
}
```

### Corrected Code (After)

```csharp
// Execution Context: G# Kernel (GPU)
public static partial class MyKernels
{
    [GpuKernel]
    public static void Kernel(int[] output)
    {
        // ✅ Correct: GPU execution members are valid inside [GpuKernel]
        int index = ThreadIndex.X;
        output[index] = index;
        Gpu.SyncThreads();
    }
}
```
