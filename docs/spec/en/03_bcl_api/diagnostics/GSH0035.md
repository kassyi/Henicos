# GSH0035

## Cannot call parallel-dependent processing from a single-thread context

| | |
| :--- | :--- |
| **Category** | GSharpTranspiler |
| **Severity** | Error |

## Cause

A method, operator, constructor, or property that relies on cooperative parallel execution (such as `Gpu.GridStrideLoop`, `Gpu.SyncGrid`, or thread-specific built-ins like `Gpu.ThreadIndex`) was invoked from within a single-thread context. 

Single-thread contexts include:
- The body of `Gpu.SingleThread(() => { ... })`
- Manual divergent branches restricting execution to a single thread, e.g., `if (Gpu.ThreadIndex.X == 0)`

## Rule Description

GPU execution is heavily parallel by default. When a method containing a parallel cooperative construct (e.g., `GridStrideLoop`) is executed by all threads in the grid, the workload is distributed properly. 

However, if that same method is invoked from a single-thread context, only one thread (usually Thread 0) will enter the method. This causes **partial compute**, where only the first iteration of the loop is processed and the rest of the buffer is ignored. Similarly, calling `Gpu.SyncGrid()` from a single-thread context will result in a **GPU deadlock** because the remaining threads will never reach the synchronization barrier.

Because C# abstracts away the internal logic of method calls and overloaded operators, the G# Roslyn Analyzer uses semantic automated inference to track parallel dependencies across the call graph and prevents you from making this contextual mistake.

## How to Fix Violations

To fix this error, you must align the execution context of the caller with the expectations of the callee.

**1. Unwrap from the single-thread context (Recommended)**

If the method performs a heavy computation that should be parallelized across the GPU, do not wrap it in a single-thread constraint.

```csharp
[GpuDevice]
public static void ExecuteSub(int[] buffer)
{
    // Parallel-dependent: uses GridStrideLoop across the grid
    Gpu.GridStrideLoop(0, buffer.Length, i =>
    {
        buffer[i] *= 2;
    });
}

[GpuKernel]
public static void BadExample(int[] buffer)
{
    // ❌ GSH0035: ExecuteSub requires parallel execution across threads, 
    // but is called from a single-thread block.
    Gpu.SingleThread(() => 
    {
        ExecuteSub(buffer); 
    });
}

[GpuKernel]
public static void GoodExample(int[] buffer)
{
    // ✅ Let the parallel-dependent method run across all threads.
    ExecuteSub(buffer); 
}
```

**2. Use a sequential alternative**

If you genuinely need to perform the operation on a single thread (e.g., initializing a buffer or orchestrating step transitions), use a sequential implementation (such as a standard `for` loop) rather than a parallel-dependent function.

```csharp
[GpuDevice]
public static void ExecuteSubSequential(int[] buffer)
{
    // Safe for single-thread execution: does not depend on thread-level parallelism
    for (int i = 0; i < buffer.Length; i++)
    {
        buffer[i] *= 2;
    }
}

[GpuKernel]
public static void SequentialExample(int[] buffer)
{
    // ✅ Safe: Sequential implementation executed on Thread 0 only.
    Gpu.SingleThread(() =>
    {
        ExecuteSubSequential(buffer);
    });
}
```
