# GSH0061

## Device functions that reach a barrier cannot be recursive

|  |  |
| :--- | :--- |
| **Category** | GSharpTranspiler |
| **Severity** | Error |

## Cause

A `[GpuDeviceFunction]` reaches `Gpu.SyncThreads()`, `Gpu.SyncGrid()` or a `Warp.Shuffle*` call, and it calls itself directly or through a cycle of other device functions.

## Rule Description

On the CPU dialects, every thread of a block runs as a state machine that suspends at each barrier. A device function that reaches a barrier is lowered into its own state machine, and each call site keeps that function's frame (its state, hoisted locals and the frames of its own calls) inside the caller's frame. A recursive call would need a frame that contains itself, so the frame has no static size and cannot be generated.

Device functions without barriers may still be recursive; they are emitted as ordinary functions.

## How to Fix

Rewrite the recursion as a loop, or move the barrier out of the recursive part.

## Examples

### Code with Warning / Error (Before)

```csharp
[GpuDeviceFunction]
public static void Reduce(int depth)
{
    if (depth <= 0) return;
    Gpu.SyncThreads();
    // ❌ Error GSH0061: the call needs a frame that contains this function's own frame
    Reduce(depth - 1);
}
```

### Corrected Code (After)

```csharp
[GpuDeviceFunction]
public static void Reduce(int depth)
{
    for (int i = depth; i > 0; i--)
    {
        // ✅ Correct: a loop around the barrier is lowered into states of one frame
        Gpu.SyncThreads();
    }
}
```
