# GSH0083

## Barrier that only some threads may reach, depending on the launch or on run-time values

|  |  |
| :--- | :--- |
| **Category** | GSharpTranspiler |
| **Severity** | Warning |

## Cause

A `Gpu.SyncThreads()`, a `Gpu.SyncGrid()`, or a call to a `[GpuDeviceFunction]` that reaches one, is reached by only some of the threads that must all reach it, in one of the ways [GSH0037](GSH0037.md) describes, but the branch that decides it does not **certainly** diverge. Whether it diverges depends on the launch configuration or on values known only at run time. Examples:

- `if (ThreadIndex.X < 16)`: every thread takes the branch when the block has at most 16 threads.
- `if (ThreadIndex.Y == 0)`: every thread takes the branch in a one-dimensional launch.
- `if (buffer[ThreadIndex.X] > count)`, `for (int i = ThreadIndex.X; i < count; i += BlockDimension.X)`: the outcome depends on run-time values.
- A call to a device function that leaves early in some threads (`if (ThreadIndex.X >= n) return;`) and is followed by a barrier.
- A call whose argument makes a barrier of the callee diverge, when the argument is not `ThreadIndex.X` itself (`SyncIf(ThreadIndex.X + 1)`), and any such call to a device function of another assembly.

The same forms are [GSH0037](GSH0037.md) (an error) when the branch certainly diverges: thread 0 and thread 1 of a block take different sides of it (block 0 and block 1 of the grid for a grid barrier), as in `if (ThreadIndex.X % 2 == 0)` or `if (Gpu.LaneId() == 0)`.

## Rule Description

On the GPU a barrier that only some threads of the block reach is undefined behavior, and the CPU dialects split the kernel into phases at each barrier, so a barrier that some threads skip reorders the shared memory accesses of the others without any error. The analyzer cannot tell whether such a branch diverges in the launches the program makes, so it warns instead of rejecting code that may be correct (a block of exactly 16 threads, a one-dimensional launch, a guard that the caller already took).

## How to Fix

- Move the barrier out of the branch, so that every thread reaches it.
- Or make the branch uniform: decide it on a kernel argument or on a value every thread of the block computes the same way.
- If the branch is a guard that a caller already took (for example a bounds check repeated in a device function), remove the repeated guard.

## Examples

```csharp
[GpuKernel]
public static void Kernel(int[] data, int n)
{
    int tid = ThreadIndex.X;
    if (tid < 16)
    {
        Gpu.SyncThreads(); // GSH0083: diverges when the block has more than 16 threads
    }

    if (tid < n)
    {
        data[tid] += 1;
    }

    Gpu.SyncThreads(); // every thread reaches this one
}
```
