# GSH0005: GpuBigIntExpr must be assigned via .Value

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0005 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### Host-Side Expression Templates and Silent Data Loss Prevention
`GpuBigInteger` and `GpuBigIntExpr` are **Host-Side Orchestration APIs** located in `Kassyi.GSharp.Stdlib.Math.BigInt`. They are executed on the host CPU to manage, chain, and launch arbitrary-precision arithmetic kernels on the GPU without intermediate memory overhead. **They cannot be used inside device-side `[GpuKernel]` methods.**

1. **Avoiding Intermediate GPU Allocations**: In high-precision arithmetic (e.g., 256-bit or 1024-bit cryptography), an expression like `(a + b) * c` would naively allocate a temporary GPU buffer for `(a + b)` and launch two separate kernels. To prevent this, G# uses **Host-Side Expression Templates**: arithmetic operators return a lightweight lazy struct `GpuBigIntExpr` that builds a symbolic expression tree in host memory.
2. **The Hazard of Local Storage**: If a developer writes `var sum = a + b;`, no GPU kernel is launched, and no result buffer is populated. If `sum` is never evaluated into a target buffer, the calculation is silently discarded.
3. **Compile-Time Enforcement**: To prevent developers from accidentally holding onto un-evaluated expression templates, the `GpuBigIntExprAnalyzer` reports **GSH0005** whenever a `GpuBigIntExpr` is declared as a local variable or stored in a field, forcing immediate evaluation into a destination buffer (`dest.Value = expr;`) or an explicit `.Evaluate()` call.

## Cause

A `GpuBigIntExpr` returned from an operator overload (such as `+`, `-`, `*`, `/`) was assigned to a local variable (`var` or `GpuBigIntExpr`) or field on the host, instead of being immediately evaluated into a target buffer.

## How to Fix

- Assign the expression directly to the destination buffer: `destination.Value = a + b;`
- Or evaluate it into a designated device buffer using `(a + b).Evaluate(dest);`.

## Examples

### Code with Warning / Error (Before)

```csharp
// Execution Context: Host (CPU)
using Kassyi.GSharp.Stdlib.Math.BigInt;

public class CryptographyHostService
{
    public void ComputeKeys(GpuBigInteger a, GpuBigInteger b, GpuBigInteger destination)
    {
        // ❌ Error GSH0005: Direct assignment or local declaration of GpuBigIntExpr is not supported.
        // Storing the lazy expression template in a local variable leaves the computation unexecuted.
        var sum = a + b;
    }
}
```

### Corrected Code (After)

```csharp
// Execution Context: Host (CPU)
using Kassyi.GSharp.Stdlib.Math.BigInt;

public class CryptographyHostService
{
    public void ComputeKeys(GpuBigInteger a, GpuBigInteger b, GpuBigInteger destination)
    {
        // ✅ Correct: Immediately evaluates the expression template into the destination GPU buffer
        destination.Value = a + b;
    }
}
```
