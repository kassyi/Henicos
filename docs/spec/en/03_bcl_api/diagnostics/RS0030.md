# RS0030: Banned API usage (BannedApiAnalyzers)

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | RS0030 |
| **Category** | BannedApiAnalyzers (`Microsoft.CodeAnalysis.BannedApiAnalyzers`) |
| **Severity** | Error |
| **Enabled by Default** | Yes |

> [!IMPORTANT]
> **Who sees RS0030:** `BannedSymbols.txt` and `BannedSymbols.Linq.txt` are loaded by the `Directory.Build.props` of the G# repository, so RS0030 applies to the projects built inside that repository (the compiler, the runtime, the standard library and their tests). The G# package does not ship these files, and a project that references G# does not get RS0030 from it. In such a project, LINQ inside a kernel is reported by **[GSH0008](GSH0008.md)**, and GPU intrinsics called from host code by **[GSH0018](GSH0018.md)**.

## Why This Rule Exists (Architectural Context)

The G# repository enforces strict safety and architecture boundaries on its own code via `Microsoft.CodeAnalysis.BannedApiAnalyzers` configured through `BannedSymbols.txt` and `BannedSymbols.Linq.txt`. This analyzer rule triggers when prohibited .NET APIs are referenced:

### 1. Banned .NET APIs (Enforcing Static Determinism & Zero-Allocation)
Standard .NET features that depend on dynamic runtime infrastructure or heap allocations cannot be used in GPU pipelines:
- **LINQ (`System.Linq`)**: Relies on dynamic delegates, closures, heap allocations (`IEnumerable<T>`), and boxing—fundamentally violating the **Zero-Allocation** and **Static Determinism** tenets. Use `Kassyi.ZeroAlloc.Linq` (StackLinq) or imperative loops instead.
- **Regular Expressions (`System.Text.RegularExpressions.Regex`)**: Prohibited due to dynamic compilation and non-deterministic overhead; use Roslyn or string matching operations.
- **Reflection (`System.Reflection.*`, `Type.GetMethod`, `Activator.CreateInstance`)**: Dynamic member resolution and metadata inspection cannot be translated to static native CUDA C++ / PTX code.

> [!NOTE]
> **Boundary Diagnostics (RS0030 vs. GSH0018):**
> While `RS0030` governs banned BCL symbols listed in `BannedSymbols.txt`, attempting to invoke GPU-only intrinsics (`ThreadIndex`, `BlockDimension`, `Gpu.SyncThreads`) from host CPU methods is detected and diagnosed separately by **[GSH0018](GSH0018.md)** (`HostIntrinsicAnalyzer`).

## Cause

Your code referenced an API explicitly listed in `BannedSymbols.txt` or `BannedSymbols.Linq.txt`:
1. Using banned LINQ methods (`.Where()`, `.Select()`, etc.) instead of StackLinq or imperative loops.
2. Using banned types such as `Regex` or unapproved reflection APIs.

## How to Fix

- **If using LINQ in kernels or performance-critical paths:** Replace `System.Linq` calls with `Kassyi.ZeroAlloc.Linq` (StackLinq) via `.AsStackEnumerable()`, or write zero-allocation loops driven by `ThreadIndex.X`.
- **If invoking GPU intrinsics on the CPU:** Note that GPU intrinsics may only be called inside `[GpuKernel]` or `[GpuDeviceFunction]` methods (see `GSH0018`). Launch the kernel using its generated `Launch{Kernel}` method.

## Examples

### Scenario 1: Using LINQ inside a GPU Kernel

#### Code with Error (Before)

```csharp
// Execution Context: G# Kernel (GPU)
using System;
using System.Linq;
using Kassyi.GSharp.Core;

public static class KernelCollection
{
    [GpuKernel]
    public static void FilterEvenNumbers(Span<int> input, Span<int> output)
    {
        // ❌ Error RS0030 inside the G# repository: The API 'System.Linq.Enumerable' is banned in this project.
        // ❌ Error GSH0008 in any project that uses G#: LINQ is not allowed in GPU kernels.
        // Reason: LINQ allocates closures, enumerators, and delegates on the GC heap.
        var evens = input.ToArray().Where(x => x % 2 == 0);
    }
}
```

#### Corrected Code (After)

```csharp
// Execution Context: G# Kernel (GPU)
using System;
using Kassyi.GSharp.Core;

public static class KernelCollection
{
    [GpuKernel]
    public static void FilterEvenNumbers(Span<int> input, Span<int> output)
    {
        // ✅ Correct: Direct zero-allocation index-based parallel processing
        int tid = ThreadIndex.X + BlockIndex.X * BlockDimension.X;
        if (tid < input.Length)
        {
            int val = input[tid];
            if (val % 2 == 0)
            {
                output[tid] = val;
            }
        }
    }
}
```

### Scenario 2: Invoking GPU Intrinsics on Host CPU (GSH0018 Boundary)

#### Code with Error (Before)

```csharp
// Execution Context: Host (CPU)
using System;
using Kassyi.GSharp.Core;

public class HostApplication
{
    public static void Main()
    {
        // ❌ Error GSH0018: GPU intrinsic called from host
        // ThreadIndex is designed for GPU device execution and cannot be read on the CPU host.
        int currentThread = ThreadIndex.X;
        Console.WriteLine($"Running on thread: {currentThread}");
    }
}
```

#### Corrected Code (After)

```csharp
// Execution Context: Host (CPU)
using System;
using Kassyi.GSharp.Core;

public class HostApplication
{
    public static void Main()
    {
        // ✅ Correct (CPU context): Use host thread information or iteration counters
        int hostThreadId = Environment.CurrentManagedThreadId;
        Console.WriteLine($"Running on CPU thread: {hostThreadId}");

        // If GPU execution is required, launch the kernel onto the device:
        // The launcher of a Span<int> parameter takes the host array and copies it to and from the device.
        int[] data = new int[1024];
        VectorKernels.LaunchVectorKernel(data, gridDimX: 4, blockDimX: 256);
    }
}

public static partial class VectorKernels
{
    [GpuKernel]
    public static void VectorKernel(Span<int> data)
    {
        // ✅ Correct: ThreadIndex is valid inside [GpuKernel]
        int tid = ThreadIndex.X + BlockIndex.X * BlockDimension.X;
        data[tid] = tid * 2;
    }
}
```
