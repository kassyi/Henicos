# GSH0110: The launcher of a [CudaImport] method cannot pass a parameter to the kernel

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0110 |
| **Category** | GSharpCompiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

G# generates the body of a `[CudaImport]` method: it loads the external kernel from its module and passes the
parameters to `cuLaunchKernel`, each by the address of a copy on the launcher's stack. An array of unmanaged elements
is first copied to a device buffer (a multidimensional array in row-major order; null reaches the kernel as a null
pointer for a nullable array and throws `ArgumentNullException` for another), and a `ref`, `out` or `in` unmanaged
value to a one-element device buffer; the kernel receives a pointer to the buffer, and the launcher copies the buffer
back after the launch.

That is a faithful translation only for unmanaged values, pointers and such arrays. A reference would reach the kernel
as the host address of the managed object, which the kernel cannot use and which reads or writes the wrong memory
without any error. `Nullable<T>` has no counterpart in a kernel. A jagged array is an array of references to other
arrays, which the launcher does not translate into a table of device pointers yet. G# reports such a parameter instead
of generating a launch with a wrong value, and the generated method throws
`NotSupportedException` with the same message, so that the rest of the project still compiles and the build shows
GSH0110.

The parameters named `gridDimX`, `gridDimY`, `gridDimZ`, `blockDimX`, `blockDimY`, `blockDimZ`, `sharedMemBytes` and
`stream` set the launch instead of passing a kernel argument. A parameter with one of these names and another type
(`int stream`, which would otherwise become the stream handle) is reported as well.

## Cause

A parameter of a `[CudaImport]` method is one of the following. The message names the parameter, the method, its type
and the reason.

- A reference type (`string`, `object`, a class, an interface, a delegate), or a struct that contains references.
- A struct with `LayoutKind.Auto`, or one that holds such a struct in a field: a tuple (`ValueTuple`), `DateTime`, a
  struct declared with `[StructLayout(LayoutKind.Auto)]`. The runtime may reorder its fields (`(byte, double)` keeps
  the `double` first), so the kernel would read them at other offsets than its C declaration names.
- A ref struct (`Span<T>`, `ReadOnlySpan<T>`), which cannot leave the launcher's stack.
- An array whose elements are references, pointers, `Nullable<T>` or structs with `LayoutKind.Auto`.
- `Nullable<T>` (`int?`).
- A `ref`, `out` or `in` parameter whose type is not an unmanaged value: a pointer, an array or one of the types
  above.
- A jagged array (`float[][]`).
- A launch setting name of the wrong type: the dimensions and `sharedMemBytes` must convert implicitly to `uint` (a
  user-defined implicit conversion included), and `stream` must be `IntPtr` (`nint`). A launch setting passed by
  `ref`, `out` or `in` is reported as well.

## How to Fix

Pass the data in a form the kernel can receive: an array of unmanaged elements for a buffer, a `ref` or `out`
unmanaged value for a value the kernel writes back, the flattened elements of a jagged array, and the correct type,
passed by value, for a launch setting.

## Examples

### Code with Error (Before)

```csharp
// Execution Context: Host (CPU)
public static partial class NativeKernels
{
    [CudaImport("kernels.fatbin")]
    public static partial void Count(float[][] rows, ref int count, int stream); // error GSH0110 (rows, stream)
}
```

### Corrected Code (After)

```csharp
// Execution Context: Host (CPU)
public static partial class NativeKernels
{
    // The rows are flattened into one array; the kernel writes *count; the stream is a CUstream handle
    [CudaImport("kernels.fatbin")]
    public static partial void Count(float[] rows, int rowLength, ref int count, IntPtr stream);
}
```
