# GSH0062

## A call that suspends at a barrier is not supported in this context

|  |  |
| :--- | :--- |
| **Category** | GSharpTranspiler |
| **Severity** | Error |

## Cause

A warp shuffle (`Warp.Shuffle*Sync`, `Gpu.MatchAnySync`, `Gpu.MatchAllSync`), or a `[GpuDeviceFunction]` that reaches `Gpu.SyncThreads()`, `Gpu.SyncGrid()` or a warp shuffle, directly or through other device functions, is called from one of these places in a kernel or device function:

- a lambda, an anonymous method or a local function (the bodies of `Gpu.ForUnroll` and `Gpu.SyncGrid(body)` are not lambdas here; the body of `Gpu.GridStrideLoop` is, but a warp shuffle written directly in it is not reported yet, although the CPU paths do not split it either)
- an arm of a `switch` expression, or a `when` clause
- the part after `?.`, or the right operand of `??`
- for such a device function only: a call that passes a `ref`, `out` or `in` argument other than a local, a parameter, a field or an array element (for example `ref GetRef()`)

## Rule Description

On the CPU dialects every thread of a block runs as a state machine that suspends at each barrier. A call to a device function that reaches a barrier suspends the caller, so the caller's body is split into states at that call and the call is made again on every resume until it completes.

A warp shuffle splits the state machine in the same way: every lane of the block writes its value before any lane reads another lane's value. Only the statements of the kernel or device function body are split this way. The compiler also turns the operands of `&&`, `||` and `?:` into `if` statements first. The places listed above are not part of that state machine, so a suspended call there could not be resumed, and a warp shuffle there would read a lane that has not written its value yet, or run where C# does not evaluate it. A by-reference argument computed by an expression, such as the result of a method that returns by reference (`ref Select(cells, i)`, also through a member access as in `ref Select(cells, i).F`, and also when it is passed to an `in` parameter without the `in` keyword), would be computed again on every resume and could refer to a different variable each time.

Calls to device functions that never reach a barrier are not affected. On CUDA the same code would run, but the error is reported for every target, so that a kernel builds and behaves the same on all of them.

## How to Fix

Move the call into a statement of the kernel or device function body, store its result in a local, and use the local in the original place. For a by-reference argument, store the reference in a `ref` local first, or pass the array element directly.

## Examples

### Code with Warning / Error (Before)

```csharp
[GpuDeviceFunction]
public static int Broadcast(int value) => Warp.ShuffleSync(0xFFFFFFFFu, value, 0);

[GpuKernel]
public static void Kernel(int[] buffer, int mode)
{
    // ❌ Error GSH0062: a switch expression arm is not split into states
    buffer[ThreadIndex.X] = mode switch
    {
        0 => Broadcast(buffer[ThreadIndex.X]),
        _ => buffer[ThreadIndex.X]
    };
}
```

### Corrected Code (After)

```csharp
[GpuKernel]
public static void Kernel(int[] buffer, int mode)
{
    int value = buffer[ThreadIndex.X];
    if (mode == 0)
    {
        // ✅ Correct: the call is a statement of the kernel body
        value = Broadcast(value);
    }

    buffer[ThreadIndex.X] = value;
}
```
