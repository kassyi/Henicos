# GSH0103: Error site ID collision in device error channel

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0103 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

The G# device error channel records source locations (file, line, column, member name, and default error message) using deterministic 31-bit site IDs computed from the source location span and trap kind. At runtime on CUDA and CPU native, device traps store this site ID so the host can reconstruct the exact source coordinates and throw matching .NET exceptions (#729).

If two distinct error sites in the same compiled module produce the exact same 31-bit site ID, the host error mapper cannot unambiguously resolve which source line triggered the trap. The compiler detects this collision during module symbol assembly and reports GSH0103 rather than failing with an opaque internal error.

## Cause

Two different expressions or trap locations within the compilation unit produced the same 31-bit FNV-1a site hash. While mathematically possible, this is exceedingly rare given the 31-bit hash space.

## How to Fix

Slightly reformat or adjust the source code around one of the colliding sites (e.g. rename a local variable, adjust whitespace, or extract a subexpression) to alter its source span and yield a distinct site ID.
