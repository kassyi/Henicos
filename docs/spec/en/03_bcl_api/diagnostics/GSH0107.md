# GSH0107: A method without [GpuDeviceFunction] is called from GPU code

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0107 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

G# compiles a method of your project for the GPU only when you mark it with `[GpuDeviceFunction]`. The attribute is the marker that says the method is meant to run on the device: G# then checks its body against the rules of GPU code and emits it next to the kernels that call it. A method without the marker stays a host method. Calling it from a kernel would make the device code call a function that does not exist there, so G# reports the call instead of letting the native build fail.

Instance methods of structs (`value.Reset()`) have no device form yet, with or without the attribute ([GSH0066](GSH0066.md)). Computed properties and constructors of structs are emitted and can be used.

## Cause

A `[GpuKernel]` or `[GpuDeviceFunction]` method calls an ordinary method declared in the same project that is not compiled for the GPU:

- a static method without `[GpuDeviceFunction]`, of a class or of a struct (generic or not);
- an instance method of a struct;
- an interface or abstract method, called through a constrained type parameter.

Not reported: methods that are mapped to native functions (`[CudaIntrinsic]`, `[CudaImport]`, operator macros, BCL intrinsics, a project method mapped with `[BclIntrinsicMap]`), and calls that C# removes: a partial method without an implementation, and a `[Conditional]` method whose condition symbol is not defined at the call. A `[Conditional]` method whose symbol is defined is reported like any other method.

The transpiler makes this decision when it writes the call, and the analyzer reports what the transpiler reports, so the diagnostic and the generated code always agree.

## How to Fix

Mark a static method with `[GpuDeviceFunction]`. Turn an instance method of a struct into a static `[GpuDeviceFunction]` method that takes the struct as a parameter (`ref` when it changes the struct), or into a computed property. Call a static `[GpuDeviceFunction]` method of the concrete type instead of an interface method.

A static `[GpuDeviceFunction]` method of a generic struct cannot return the struct itself yet (`GBox<T> Make(T v)` is rejected with [GSH0004](GSH0004.md)); one that returns another type, such as `int`, works.

## Examples

### Code with Error (Before)

```csharp
public struct Box
{
    public int Value;

    public static Box Make(int v) => new Box { Value = v };

    public void Set(int v) { Value = v; }
}

public static class Helpers
{
    public static int Twice(int v) => v * 2;
}

public static partial class Kernels
{
    [GpuKernel]
    public static void Fill(int[] output)
    {
        var box = Box.Make(5);            // GSH0107: Box.Make has no [GpuDeviceFunction]
        box.Set(7);                       // GSH0107: instance methods of structs are not supported yet
        output[0] = Helpers.Twice(box.Value); // GSH0107: Helpers.Twice has no [GpuDeviceFunction]
    }
}
```

### Corrected Code (After)

```csharp
public struct Box
{
    public int Value;

    [GpuDeviceFunction]
    public static Box Make(int v) => new Box { Value = v };

    [GpuDeviceFunction]
    public static void Set(ref Box box, int v) { box.Value = v; }
}

public static class Helpers
{
    [GpuDeviceFunction]
    public static int Twice(int v) => v * 2;
}

public static partial class Kernels
{
    [GpuKernel]
    public static void Fill(int[] output)
    {
        var box = Box.Make(5);
        Box.Set(ref box, 7);
        output[0] = Helpers.Twice(box.Value);
    }
}
```
