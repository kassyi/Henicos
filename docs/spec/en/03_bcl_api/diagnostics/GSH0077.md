# GSH0077

## Dynamic SharedMemory<T> reached by only some threads or with a thread-dependent count

|  |  |
| :--- | :--- |
| **Category** | GSharpTranspiler |
| **Severity** | Warning |

## Cause

One of the following, in a `[GpuKernel]` or a `[GpuDeviceFunction]`:

- A **dynamic** `SharedMemory<T>` declaration (its count is not a C# constant) is under a condition that may differ between the threads of a block: an `if`, `switch` or loop whose condition is thread-variant, a branch of `?:`, an arm of a `switch` expression, or the right operand of `&&`, `||` or `??`.
- A call to a `[GpuDeviceFunction]` that reaches a dynamic declaration, directly or through other device functions, is under such a condition.
- The count of a dynamic declaration is thread-variant (for example `new SharedMemory<int>(n + ThreadIndex.X)`).

The conditions are the ones of [GSH0083](GSH0083.md), plus the arms of a `switch` expression, with the same definition of a [thread-variant value](GSH0083.md#thread-variant-values). The warning is reported in every dialect.

Each declaration or call is reported once for each kind, however many thread-variant conditions enclose it: a declaration that is under a thread-variant condition and also has a thread-variant count gets two warnings, one at the `new` expression and one at the count.

## Rule Description

On CUDA every dynamic `SharedMemory<T>` declaration is one region of the launch's dynamic shared memory per block, and the regions are placed in the order a thread **first reaches** them (see [Dynamic Shared Memory](../memory/SharedMemory.md#dynamic-shared-memory)). Each thread keeps its own table of the regions: it places a region where its own table says the buffer ends, with the count it computed.

All threads of the block therefore agree on the layout only when they reach the dynamic declarations in the same order and with the same counts. When only some threads reach a declaration first, or the counts differ, a later region can start at different offsets in different threads, and the threads read and overwrite each other's data without any error. The CPU and managed runtimes keep one table per block, filled by the first thread to arrive, so the same kernel may also compute different results on the CPU and on the GPU.

It is a warning, not an error, because the layout still agrees when no other dynamic declaration is placed after the divergent one and its count does not matter for the others.

## Limitations

The analysis looks at the conditions that enclose a declaration or call in the source, within one method. It does not detect:

- a declaration or call after a `return` under a thread-variant condition, or one that a `goto` jumps over;
- a declaration or call in a local function or lambda that is itself called in a thread-variant branch;
- a declaration or call in the body of `Gpu.GridStrideLoop` or `Gpu.SingleThread`, which only some threads run;
- a count that depends on the thread through an argument: a parameter is assumed uniform, as for GSH0083, so `Scratch(ThreadIndex.X)` with `new SharedMemory<int>(n)` inside `Scratch` is not reported.

An early `return` in a kernel before every dynamic declaration is harmless: the threads that leave place nothing, and the others place the same regions in the same order. The harmful cases are an early `return` inside a device function, and a `break` or `continue` in a loop, after which some threads reach a later declaration first.

## How to Fix

Declare dynamic shared memory where every thread of the block reaches it, with a count that every thread computes alike (a kernel argument, `BlockDimension.X`), and branch afterwards. Call a device function that declares dynamic shared memory outside thread-dependent branches. If each thread needs a different amount, declare the largest amount once and index into it.

## Examples

### Code with Warning (Before)

```csharp
[GpuKernel]
public static void HalfKernel(int[] output, int n)
{
    int tid = ThreadIndex.X;
    if (tid < 16)
    {
        // Warning GSH0077: only the threads with tid < 16 reach the declaration
        var half = new SharedMemory<int>(n);
        half[tid] = tid;
        output[tid] = half[tid];
    }

    // Warning GSH0077: the count depends on the thread
    var perThread = new SharedMemory<int>(n + tid);
    perThread[0] = tid;
}
```

### Corrected Code (After)

```csharp
[GpuKernel]
public static void HalfKernel(int[] output, int n)
{
    int tid = ThreadIndex.X;

    // Every thread reaches both declarations, in the same order and with the same counts
    var half = new SharedMemory<int>(n);
    var perThread = new SharedMemory<int>(n + BlockDimension.X);
    if (tid < 16)
    {
        half[tid] = tid;
        output[tid] = half[tid];
    }

    perThread[tid] = tid;
}
```
