# GSH0089: Device code of another assembly cannot be used

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0089 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

A referenced assembly records the transpiled C++ of its device functions and structs (`[assembly: GpuDeviceExport]`, see [GSH0088](GSH0088.md)). The consumer copies that text into its own native module, after its own prelude. The text is only valid for the prelude it was written for, and only when the library's build could transpile it for the consumer's dialect.

The message names the reason:

- **Written by another version of G#**: the record layout differs from the consumer's compiler, or the hash of what the text was written for: the CUDA and C++ preludes and the spelling of the generated names (`InternalNames.yml`). Text written for another prelude or another name spelling may not compile, or may compile with another meaning.
- **Could not be transpiled for the dialect**: the library's build met a construct it could not emit for CUDA or for C++. The library reports the construct itself when it builds for that dialect; a library built for CUDA only reports its CUDA failures.
- **No managed state machine**: the function waits at a barrier (it suspends), and the library holds no managed state machine for it, which the managed form of the call runs: the managed fallback of the C++ dialect, or the state machine of a device function of an assembly that exports its device code. The library leaves it out when it could not compile: a containing type that is not `partial`, a type of its locals or parameters that is less visible than `internal`, or a suspending callee without one.
- **The generator failed with an exception**: the message adds the exception's type and message, which the record keeps (`InternalError`). The library's build does not stop for it when no device code of the library uses the failed part; report it as a G# bug.

The same applies to what the recorded text calls in turn: a library function whose internal helper could not be transpiled for C++ is reported at its use, with the name of the helper.

## How to Fix

- Rebuild the referenced assembly with the same G# version as the consumer.
- For a construct the library could not transpile, build the library for the consumer's dialect, read its diagnostics, and change the device function there.

## Example

```csharp
// Library, built for CUDA: Twice calls the internal Helper, which uses a construct that G# can emit for CUDA only
public static partial class LibMath
{
    [GpuDeviceFunction]
    public static int Twice(int x) => Helper(x) * 2;

    [GpuDeviceFunction]
    internal static int Helper(int x) => /* ... */ x;
}

// Consumer, built for the CPU dialect
public static partial class Kernels
{
    [GpuKernel]
    public static void Run(int[] data)
    {
        // Incorrect: GSH0089, the device code of 'LibMath.Helper' cannot be used: the build of the library could not
        // transpile it for the C++ dialect
        data[ThreadIndex.X] = LibMath.Twice(data[ThreadIndex.X]);
    }
}
```
