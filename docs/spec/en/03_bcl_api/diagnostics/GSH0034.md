# GSH0034: The 'params' modifier is prohibited in GPU device code

## Details

| Property               | Value                  |
| :--------------------- | :--------------------- |
| **Diagnostic ID**      | GSH0034                |
| **Category**           | GSharp.ZeroAllocation  |
| **Severity**           | Error                  |
| **Enabled by Default** | Yes                    |

## Why This Rule Exists (Architectural Context)

### Zero-Allocation Principle

In standard C#, the `params T[]` parameter modifier allows methods to accept a variable number of arguments. However, to support this feature, the C# compiler implicitly injects a managed array allocation (`new T[] { ... }`) at the call site.

G# fundamentally enforces the **Zero-Allocation** principle on the GPU. Device code cannot allocate managed memory on the heap and does not have a Garbage Collector. Permitting `params` in `[GpuKernel]` or `[GpuDevice]` methods would lead to one of two critical failures:
1. Attempting to allocate managed arrays in GPU memory, which is prohibited.
2. Generating ambiguous or broken CUDA C++ transpilation, as C++ variadic parameters and initializer lists map poorly to C#'s managed array semantics without significant runtime overhead.

To prevent developers from accidentally writing allocating code or creating "parameter bloat" (Win32 API-style long argument lists), this diagnostic explicitly prohibits the `params` keyword.

## Cause

A method marked with the `[GpuKernel]` or `[GpuDevice]` attribute has one or more parameters defined using the `params` keyword.

## How to Fix

Remove the `params` modifier. Depending on your goal, use one of the idiomatic G# patterns:

1. **Pass a single fixed-size array/buffer**: Use `GpuBuffer<T>` or a raw pointer `T*` if you are passing a collection of items.
2. **Use a Parameter Struct**: If you are trying to group various configuration arguments to avoid "parameter bloat", group them into a single `readonly struct` and pass it by value or by reference (`in`).
3. **Use Default Parameters**: If you want to make certain arguments optional, use C# default parameters instead of a variadic list.

## Examples

### Code with Warning / Error (Before)

```csharp
public static class InvalidKernelExamples
{
    // ❌ Error GSH0034: The parameter 'items' in method 'KernelWithParams' uses the 'params' modifier, which incurs heap allocation.
    [GpuKernel]
    public static void KernelWithParams(params int[] items)
    {
    }

    // ❌ Error GSH0034: The parameter 'modifiers' in method 'DeviceHelper' uses the 'params' modifier, which incurs heap allocation.
    [GpuDevice]
    public static int DeviceHelper(int baseVal, params int[] modifiers)
    {
        return baseVal;
    }
}
```

### Corrected Code (After)

```csharp
public static class ValidKernelExamples
{
    // ✅ Correct: Use an explicit pointer or GpuBuffer for arrays
    [GpuKernel]
    public unsafe static void KernelWithPointer(int* items, int length)
    {
    }

    // ✅ Correct: Group multiple optional configuration values into a Parameter Struct
    public readonly struct DeviceConfig
    {
        public readonly int ModifierA;
        public readonly int ModifierB;
    }

    [GpuDevice]
    public static int DeviceHelper(int baseVal, in DeviceConfig config)
    {
        return baseVal + config.ModifierA + config.ModifierB;
    }
}
```
