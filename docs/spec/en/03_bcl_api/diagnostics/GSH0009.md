# GSH0009: Implicit var with literal needs suffix

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0009 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### Type Inference Ambiguity and C++ Auto Mismatch

When writing `var x = 0;` in C#, the language specification mandates that untyped integer literals default to `System.Int32` (signed 32-bit integer).

When the AOT transpiler translates this statement into CUDA C++:

1. Translating to `auto x = 0;` in C++ produces a signed 32-bit `int`.
2. In GPU kernels, memory indexing, thread coordinates (`threadIdx.x`), and buffer offsets are unsigned quantities (`unsigned int` or `size_t`).
3. Performing arithmetic between signed `int` and unsigned thread indices causes compiler signed/unsigned comparison warnings and, in 64-bit address spaces, can lead to silent sign-extension bugs that access invalid VRAM addresses.
   `GSH0009` enforces explicit intent at the C# level to eliminate type ambiguity before code generation.

## Cause

An implicitly typed variable (`var`) was initialized with an integer literal lacking a type suffix (e.g. `var i = 0;`).

## How to Fix

Add an explicit type suffix (`0U`, `0UL`, `0.0f`, `0.0`) or declare the variable with an explicit type (`uint i = 0;`).

## Examples

### Code with Warning / Error (Before)

```csharp
// Execution Context: G# Kernel (GPU)
[GpuKernel]
public static void BadKernel()
{
    // ❌ Error GSH0009: Untyped literal defaults to signed Int32, causing C++ auto type hazards
    var offset = 0;
}
```

### Corrected Code (After)

```csharp
// Execution Context: G# Kernel (GPU)
[GpuKernel]
public static void GoodKernel()
{
    // ✅ Correct: Explicit unsigned literal suffix guarantees clean C++ uint32_t translation
    var offset = 0U;
    // Or explicit type:
    uint index = 0;
}
```
