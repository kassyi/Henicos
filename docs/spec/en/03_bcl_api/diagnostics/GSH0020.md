# GSH0020: Missing IDisposable implementation

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0020 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### Strict Ownership Model and VRAM Leak Prevention
GPU native resources (such as `GpuContext`, `GpuBuffer<T>`, and pinned streams) allocate unmanaged driver handles and VRAM via the CUDA Driver API (`cuMemAlloc`). Unlike managed CPU memory, the .NET Garbage Collector has no visibility into GPU VRAM pressure.

If a host class instantiates an owned GPU resource field without implementing `IDisposable`, the resource will only be released when the finalizer runs (if implemented), which may occur long after VRAM is completely exhausted. Implementing `IDisposable` is mandatory to guarantee prompt, deterministic release.

## Cause

A class declares a field holding an `IDisposable` GPU resource but the class itself does not implement `IDisposable`.

## How to Fix

Add `: IDisposable` to the class declaration and dispose of the field in `Dispose()`.

## Examples

### Code with Warning / Error (Before)

```csharp
// Execution Context: Host (CPU)
// Error GSH0020: Class holds native GpuBuffer but fails to implement IDisposable
public class PipelineManager
{
    private GpuBuffer<float> _buffer = new GpuBuffer<float>(1024);
}
```

### Corrected Code (After)

```csharp
// Execution Context: Host (CPU)
// Correct: Deterministic cleanup via IDisposable
public class PipelineManager : IDisposable
{
    private GpuBuffer<float> _buffer = new GpuBuffer<float>(1024);

    public void Dispose()
    {
        _buffer.Dispose();
    }
}
```
