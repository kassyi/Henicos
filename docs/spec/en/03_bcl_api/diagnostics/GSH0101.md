# GSH0101: Warp.ActiveMask() under a thread-dependent condition differs on the CPU

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0101 |
| **Category** | GSharpTranspiler |
| **Severity** | Warning |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

On the GPU, `Warp.ActiveMask()` returns the lanes of the warp that reach the call together. The CPU paths (the native C++ build and the managed path) run the threads of a warp one after another, so they cannot tell which lanes would share a path on the GPU. They return every lane of the warp that exists in the block: all 32, or fewer in the last warp of a block whose size is not a multiple of 32. Where every lane of the warp reaches the call, that is the GPU result. Under a condition that depends on the thread, the GPU may return fewer lanes, and the CPU result is not the GPU result.

The CPU paths exist to reproduce the GPU result and check it, so G# warns where it cannot. The warning appears only on the CPU dialects; on CUDA the call runs as written.

## Cause

A call to `Warp.ActiveMask()` inside a branch, a loop body or condition, a switch section or arm, an operand of `?:`, `&&`, `||` or `??`, whose condition depends on the thread (`ThreadIndex`, the lane id, a warp operation, or a local computed from them), or a call after a `return`, `break` or `continue` of the same method under such a condition, such as the bounds guard `if (t >= n) { return; }`. In a device function, every parameter counts as depending on the thread, since a caller may pass a different value to each thread.

Not reported, although the GPU may return fewer lanes there too:

- A call after a loop that some threads leave early, once every thread has left it (a `break` of an inner loop or a `return` of a local function or lambda).
- A call in the body of `Gpu.GridStrideLoop`. In its last round, the threads whose index is past the end have left the loop, so the GPU may return fewer lanes than the CPU paths there.
- A call in a device function whose caller calls it under a thread-dependent condition (each method is analyzed on its own).
- A call in a device function of a library built for CUDA that exports its device code (`GSharpExportDeviceCode`, the default). The rule runs only when the library itself is built for a CPU dialect, yet its device functions can run on the managed path of a CPU project that references it.

Reported, although the CPU and the GPU agree there: a call under a condition that is the same for every lane of a warp, such as `if (warpId == 0)` with `warpId = ThreadIndex.X / 32`. The rule knows only whether a value may differ between threads, not whether it may differ within a warp. Every lane of such a warp reaches the call, so the warning can be suppressed there.

## How to Fix

Move the call before the branch (and before an early `return`), where every lane of the warp reaches it, so the CPU and the GPU agree. Otherwise keep it and run the kernel on CUDA to check its result.

On CUDA, `Warp.BallotSync` gives the lanes for which a condition holds, computed before the branch from a mask that every lane reaches. It is not available on the CPU dialects yet (#542, #845): the native C++ build does not compile it, and the managed path throws `GpuOnlyException`. So it does not make the CPU and the GPU agree there.

## Example

```csharp
[GpuKernel]
public static void Run(uint[] result)
{
    int t = ThreadIndex.X;
    // Not reported: every lane of the warp reaches the call
    result[t] = Warp.ActiveMask();
    if (t < 4)
    {
        // GSH0101: the GPU returns at most 0xF here (lanes 0 to 3; from Volta on, the lanes need not reconverge
        // before the call, so it may be fewer); the CPU paths return every lane of the warp
        result[t] = Warp.ActiveMask();
    }
}
```
