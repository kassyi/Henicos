# GSH0106: Kernel parameter name conflicts with a launch parameter

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0106 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

For every `[GpuKernel]` method, the source generator emits host launch wrappers (`Launch{Kernel}` and `Launch{Kernel}Ptr`) that append the launch configuration parameters to the kernel's own parameter list:

- `gridDimX`, `gridDimY`, `gridDimZ`
- `blockDimX`, `blockDimY`, `blockDimZ`
- `sharedMemBytes`
- `hStream`
- `macros`

Because callers pass these launch options by name (for example, `blockDimX: 256`), their names are part of the public wrapper signature. C# does not allow two parameters in the same method signature to share a name (`CS0100`), so a kernel parameter that uses one of these nine names cannot produce a valid host wrapper.

## Cause

A `[GpuKernel]` method declares a parameter named `gridDimX`, `gridDimY`, `gridDimZ`, `blockDimX`, `blockDimY`, `blockDimZ`, `sharedMemBytes`, `hStream`, or `macros`. The kernel gets no host launch wrappers.

## How to Fix

Rename the kernel parameter so that it does not match any of the launch option parameter names.

## Examples

### Code with Error (Before)

```csharp
public static partial class Kernels
{
    [GpuKernel]
    public static void Scale(int[] data, uint blockDimX) // ❌ GSH0106: conflicts with launch parameter 'blockDimX'
    {
        int i = ThreadIndex.X;
        data[i] *= (int)blockDimX;
    }
}
```

### Corrected Code (After)

```csharp
public static partial class Kernels
{
    [GpuKernel]
    public static void Scale(int[] data, uint factor) // ✅
    {
        int i = ThreadIndex.X;
        data[i] *= (int)factor;
    }
}
```
