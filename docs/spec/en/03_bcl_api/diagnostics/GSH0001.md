# GSH0001: Object creation not supported in GPU kernels

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0001 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### The Zero-Allocation GPU Paradigm
Standard C# applications rely on the Common Language Runtime (CLR) Garbage Collector (GC) to automatically track and reclaim dynamically allocated memory. In contrast, NVIDIA GPU hardware operates on a **Massively Parallel Processor (MPP)** architecture executing thousands of threads simultaneously in SIMT (Single Instruction, Multiple Threads) lockstep.

1. **Absence of a Device-Side GC**: The GPU has no garbage collector, no mark-and-sweep phases, and no memory compactor. If threads were permitted to allocate reference-type objects on a heap, thread-local allocations would rapidly fragment and exhaust VRAM within milliseconds.
2. **Object Header Overhead**: In .NET, every heap object carries an object header (MethodTable pointer, SyncBlock index) consuming 8 to 16 bytes of metadata. GPU Streaming Multiprocessors (SMs) rely on compact, register-aligned data layouts; managed object metadata would destroy memory coalescing and cache locality.
3. **Deterministic Memory**: G# strictly adheres to the **Zero-Allocation** tenet. Device memory must be statically allocated upfront on the host or in Shared Memory, while thread-local variables must reside purely in hardware registers or the thread stack frame as value types (`struct`).

## Cause

The `new` operator was used inside a `[GpuKernel]` or `[GpuDeviceFunction]` to allocate a reference type (`class`) or an array on the managed heap.

## How to Fix

Replace reference types (`class`) with unmanaged value types (`struct`). Pre-allocate all buffers upfront in host memory or GPU global memory, and pass them as pointers or array parameters into the kernel.

## Examples

### Code with Warning / Error (Before)

```csharp
// Execution Context: G# Kernel (GPU)
// ❌ Reference types (classes) reside on the managed heap
public class ParticleClass
{
    public float X, Y, Z;
}

public static class ParticleKernels
{
    [GpuKernel]
    public static void BadKernel()
    {
        // Error GSH0001: Object creation ('new') is not supported in GPU kernels
        var particle = new ParticleClass();
    }
}
```

### Corrected Code (After)

```csharp
// Execution Context: G# Kernel (GPU)
// ✅ Unmanaged value types (structs) reside on the GPU stack/registers
public struct ParticleStruct
{
    public float X, Y, Z;
}

public static class ParticleKernels
{
    [GpuKernel]
    public static void GoodKernel()
    {
        // Correct: Struct instantiation is stack-allocated with zero dynamic heap overhead
        ParticleStruct particle = new ParticleStruct();
    }
}
```
