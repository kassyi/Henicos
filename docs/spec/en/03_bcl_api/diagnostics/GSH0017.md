# GSH0017: Unroll hint must precede a loop

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0017 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### Pragma Association in AST Translation
In C++ and CUDA, `#pragma unroll` has lexical scope that binds strictly to the statement immediately following it. If an assignment, method call, or branch is placed between the pragma and the loop, the pragma is orphaned and silently discarded by the CUDA compiler, disabling loop unrolling without warning.

`GSH0017` guarantees that every `Gpu.Hint.Unroll` invocation directly decorates a loop statement in the AST.

## Cause

Statements or declarations were placed between `Gpu.Hint.Unroll` and the loop construct.

## How to Fix

Move `Gpu.Hint.Unroll` so that it immediately precedes the `for`, `while`, or `do-while` loop.

## Examples

### Code with Warning / Error (Before)

```csharp
// Execution Context: G# Kernel (GPU)
[GpuKernel]
public static void BadKernel()
{
    Gpu.Hint.Unroll(4);
    // Error GSH0017: Variable declaration separates unroll hint from loop
    int start = 0;
    for (int i = start; i < 16; i++) { }
}
```

### Corrected Code (After)

```csharp
// Execution Context: G# Kernel (GPU)
[GpuKernel]
public static void GoodKernel()
{
    int start = 0;
    // Correct: Hint immediately precedes the targeted loop
    Gpu.Hint.Unroll(4);
    for (int i = start; i < 16; i++) { }
}
```
