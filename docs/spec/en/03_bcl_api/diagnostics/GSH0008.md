# GSH0008: LINQ is not allowed in GPU kernels

## Details

| Property               | Value            |
| :--------------------- | :--------------- |
| **Diagnostic ID**      | GSH0008          |
| **Category**           | GSharpTranspiler |
| **Severity**           | Error            |
| **Enabled by Default** | Yes              |

## Why This Rule Exists (Architectural Context)

### Closure Allocations, Delegates, and GPU State Machines

Language Integrated Query (LINQ) is one of C#'s most expressive features, but its internal mechanics are entirely incompatible with GPU architectures:

1. **Delegate Closures**: LINQ operations (e.g. `.Where(x => x > 0)`) allocate delegate objects (`Func<T, bool>`) and closure classes on the managed heap to capture state.
2. **State Machine Overhead**: Methods like `.Select()` use iterator state machines (`yield return`) with complex jump tables that destroy SIMT thread synchronization.
3. **Dynamic Dispatch**: LINQ operates through interface dispatch (`IEnumerable<T>`), which prevents the CUDA compiler from inlining functions into GPU registers.

### Static Analyzer Symbol Verification

The G# validation walker (`GpuKernelValidationWalker`) enforces this rule via `LinqNotSupportedRule`:

- **Query Expressions**: Intercepts `QueryExpressionSyntax` nodes.
- **Method Invocations**: Inspects `InvocationExpressionSyntax` nodes using the Roslyn semantic model. If the resolved method belongs to the `System.Linq` namespace or is declared in `System.Linq.Enumerable` or `System.Linq.Queryable`, `GSH0008` is immediately reported at compile time.

## Cause

LINQ query syntax (`from ... in ... select`) or LINQ method syntax (invocations of extension or static methods from `System.Linq`, `System.Linq.Enumerable`, or `System.Linq.Queryable`, such as `.Where()`, `.Select()`, `.ToArray()`, etc.) was used inside device code (`[GpuKernel]` or `[GpuDeviceFunction]`).

## How to Fix

Replace LINQ queries or LINQ extension method calls with explicit imperative `for` loops, thread-indexed conditional assignments, or parallel grid-stride loops that execute directly on GPU registers without heap allocations.

## Examples

### Code with Warning / Error (Before)

```csharp
// Execution Context: G# Kernel (GPU)
using System.Linq;

public static class LinqExampleKernels
{
    [GpuKernel]
    public static void BadKernelQuerySyntax(float[] data)
    {
        // ❌ Error GSH0008: LINQ query expressions rely on delegates and heap allocations
        var positive = from x in data where x > 0.0f select x;
    }

    [GpuKernel]
    public static void BadKernelMethodSyntax(int[] data)
    {
        // ❌ Error GSH0008: LINQ extension methods (.Where, .Select, .ToArray) are prohibited in GPU kernels
        var query = data.Where(x => x > 0).Select(x => x * 2).ToArray();
    }
}
```

### Corrected Code (After)

```csharp
// Execution Context: G# Kernel (GPU)
using Kassyi.GSharp.Core;

public static class LinqExampleKernels
{
    [GpuKernel]
    public static void GoodKernel(int[] data, int[] output, int length)
    {
        int tid = ThreadIndex.X + BlockIndex.X * BlockDimension.X;

        // ✅ Correct: Explicit imperative filtering and transformation executed directly in registers
        if (tid < length && data[tid] > 0)
        {
            output[tid] = data[tid] * 2;
        }
    }
}
```
