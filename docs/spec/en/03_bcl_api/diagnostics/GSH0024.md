# GSH0024: Cast operator side-effect

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0024 |
| **Category** | GSharpTranspiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

### Hidden Allocation Semantics in Type Conversions
Developers expect type casts (`(GpuBuffer<int>)config`) to be inexpensive type conversions. Hiding a native VRAM allocation inside an implicit or explicit cast operator obscures resource ownership, making it easy for callers to omit proper `using` or `Dispose()` calls.

## Cause

An implicit or explicit cast operator instantiated an `IDisposable` GPU resource.

## How to Fix

Replace the cast operator with an explicit named factory or conversion method.

## Examples

### Code with Warning / Error (Before)

```csharp
// Execution Context: Host (CPU)
public class Config
{
    public int Length;

    // Error GSH0024: Cast operator allocates disposable native resource
    public static implicit operator GpuBuffer<int>(Config c) => new GpuBuffer<int>(c.Length);
}
```

### Corrected Code (After)

```csharp
// Execution Context: Host (CPU)
public class Config
{
    public int Length;

    // Correct: Explicit named factory method clearly communicates native resource creation
    public GpuBuffer<int> ToGpuBuffer() => new GpuBuffer<int>(Length);
}
```
