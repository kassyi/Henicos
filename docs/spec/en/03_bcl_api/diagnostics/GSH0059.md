# GSH0059: Malformed trusted key line

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0059 |
| **Category** | GSharpCompiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

The G# fatbin compilation pipeline verifies binary signatures using a set of trusted public keys specified in `trusted_keys.txt`. If a trusted public key line contains typos, invalid Base64 or hex encodings, or incorrect byte lengths, silently ignoring the line could lead to unexpected signature verification failures at runtime or security misconfigurations during deployment.

To ensure build safety and fail fast on configuration errors, the `TrustedKeysGenerator` inspects each non-empty, non-comment line in `trusted_keys.txt`. Any line that is not a valid 64-character hex key or 44-character Base64 key, followed by a matching fingerprint, triggers `GSH0059`.

## Cause

A line in `trusted_keys.txt` is malformed. Valid lines have the form `<key>,fnv1a64:<fingerprint>` (spaces or tabs around the comma are allowed):

- **Hex key:** Exactly 64 hex characters (`0-9`, `a-f`, `A-F`), decoding to 32 bytes.
- **Base64 key:** Exactly 44 characters ending with `=`, where the first 43 characters are valid Base64 characters (`A-Z`, `a-z`, `0-9`, `+`, `/`), decoding to 32 bytes.
- **Fingerprint:** `fnv1a64:` followed by exactly 10 lowercase hex characters. It is the first 10 characters of the 64-bit FNV-1a hash of the key normalized to 64 lowercase hex characters, so the hex form and the Base64 form of one key share a fingerprint.

The reported reason is one of:

| Reason | Meaning |
| :--- | :--- |
| `invalid character` / `expected 64 hex characters` / `expected 44 Base64 characters ending with '='` | The key part is not a well-formed hex or Base64 key. |
| `missing fingerprint` | The key has no `,fnv1a64:<10 hex>` suffix, or the suffix is not in the canonical form. |
| `fingerprint mismatch` | The fingerprint does not match the key, which usually means a typo in the key. |

The diagnostic deliberately does not print the expected fingerprint. Re-derive it from the key you intend to trust, instead of copying it from the message.

The fingerprint only detects typos. It is not a security feature: anyone who can edit `trusted_keys.txt` can also edit the fingerprint.

## How to Fix

Check the line number in the diagnostic and correct the key or its fingerprint. To produce a complete line from a key, run:

```
just trusted-key-line <key>
```

The recipe accepts a hex or Base64 key and prints `<key>,fnv1a64:<fingerprint>`. Standard tools such as `sha256sum` cannot compute FNV-1a. Comments starting with `#` and empty lines are permitted.

## Examples

### Code with Error (Before)

`trusted_keys.txt`:
```
# Primary Key
d75a980182b10ab7d54bfed3c964073a0ee172f3daa62325af021a68f707511a,fnv1a64:5553fd74df

# ❌ Error GSH0059: Malformed trusted key line
AAAA!!notbase64==

# ❌ Error GSH0059: missing fingerprint
d75a980182b10ab7d54bfed3c964073a0ee172f3daa62325af021a68f707511a

# ❌ Error GSH0059: fingerprint mismatch (last key character mistyped)
d75a980182b10ab7d54bfed3c964073a0ee172f3daa62325af021a68f707511b,fnv1a64:5553fd74df
```

### Corrected Code (After)

`trusted_keys.txt`:
```
# Primary Key
d75a980182b10ab7d54bfed3c964073a0ee172f3daa62325af021a68f707511a,fnv1a64:5553fd74df

# ✅ Valid Base64 key (44 characters ending with '=') with its fingerprint
1111111111111111111111111111111111111111111=,fnv1a64:25c9e1ea82
```
