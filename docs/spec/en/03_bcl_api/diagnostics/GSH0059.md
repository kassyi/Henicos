# GSH0059: A kernel declares or makes G# generate a member that its class already has

## Details

| Property | Value |
| :--- | :--- |
| **Diagnostic ID** | GSH0059 |
| **Category** | GSharpCompiler |
| **Severity** | Error |
| **Enabled by Default** | Yes |

## Why This Rule Exists (Architectural Context)

For each `[GpuKernel]` method, G# generates host members in the same type:

- `Launch{Kernel}` takes the same parameter types as the kernel.
- `Launch{Kernel}Ptr` takes device pointers: an array as a `GSharpArrayProxy`, a `ref` / `out` parameter as an `IntPtr`. For an overloaded kernel, the public `Launch{Kernel}Ptr` takes every array-like and `ref` / `out` parameter as a typed `GpuBuffer<T>` where it can, and the `IntPtr` form becomes a private `Launch{Kernel}__o{n}Ptr`.
- `WarmupFunctionPointer{Kernel}()` (`WarmupFunctionPointer{Kernel}__o{n}()` for an overload), whose suffix also names the other per-kernel members.
- With `GSharpEmitSource`, the constant `{Kernel}_Source` (`{Kernel}__o{n}_Source`).

Every class with kernels also gets the nested class `AotContexts` and, when its kernels have run-time checks, the field `s_errorSites`. Both names are reserved in every kernel class, also in one whose kernels have no run-time check and so gets no `s_errorSites`: whether the field exists depends on the bodies of the kernels, and a kernel name that is free today would collide as soon as one of them gets a check.

C# rejects two methods with the same name and parameter types, and a field, constant or nested type that has the name of any other member. Kernels that C# can tell apart can still reach that:

- Overloads: `int[] data` and `ref int value` are both a `GpuBuffer<int>` in `Launch{Kernel}Ptr`, and `in int x` and `int x` are both `int x` in `Launch{Kernel}`.
- Kernels with different names: the `Launch{Kernel}Ptr` of `Scale(ref S s)` and the `Launch{Kernel}` of `ScalePtr(nint address)` are both `LaunchScalePtr(IntPtr)`.
- A generated member and another kernel's own method: the `WarmupFunctionPointerFoo()` of `Foo` and a kernel `WarmupFunctionPointerFoo()`; with `GSharpEmitSource`, the constant `LaunchX_Source` of a kernel `LaunchX` and the method `X_Source` (or the launcher `LaunchX_Source` of a kernel `X_Source`).
- A kernel named `AotContexts` or `s_errorSites` (reserved in every kernel class).

G# reports the conflict instead of generating code that does not compile. The kernels' own methods always stay; of two generated members, the one of the kernel whose name sorts first (by ordinal comparison), or for overloads the one declared first, stays. The reported kernel gets no host members. A kernel named like a member of every kernel class leaves the whole class without host members, since leaving the kernel out does not remove the collision. The check does not depend on the dialect, so that the same source builds for both CPU and CUDA (`{Kernel}_Source` counts only with `GSharpEmitSource`).

## Cause

A `[GpuKernel]` method declares, or makes G# generate, a member that its class already has. The message names that member and what else declares or generates it.

## How to Fix

Rename the reported kernel.

## Examples

### Code with Error (Before)

```csharp
public static partial class Kernels
{
    [GpuKernel]
    public static void Fill(int[] data) { data[ThreadIndex.X] = 1; }

    [GpuKernel]
    public static void Fill(ref int value) { value = 2; } // ❌ GSH0059: both are Fill(GpuBuffer<int>) in LaunchFillPtr
}
```

```csharp
public struct Bag { public int[] Items; }

public static partial class Kernels
{
    [GpuKernel]
    public static void Scale(ref Bag bag) { bag.Items[ThreadIndex.X] *= 2; }

    [GpuKernel]
    public static void ScalePtr(nint address) { } // ❌ GSH0059: both produce LaunchScalePtr(IntPtr)
}
```

### Corrected Code (After)

```csharp
public static partial class Kernels
{
    [GpuKernel]
    public static void Fill(int[] data) { data[ThreadIndex.X] = 1; }

    [GpuKernel]
    public static void FillOne(ref int value) { value = 2; } // ✅
}
```
