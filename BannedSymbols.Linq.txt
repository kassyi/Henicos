# System.Linq bans for product code (Microsoft.CodeAnalysis.BannedApiAnalyzers; format: see the root BannedSymbols.txt).
# The root Directory.Build.props loads this file for every project except the test projects
# (GSharpAllowsSystemLinq in tests/Directory.Build.props): tests may use System.Linq and StackLinq alike.
# tools/fuzz-diff/Directory.Build.props loads it as well, since fuzz-diff does not import the root props.

# Why: System.Linq allocates (enumerator boxing, delegates, closures) on every call.
# Instead: the StackLinq operator of the same name (using Kassyi.ZeroAlloc.Linq), started with .AsStackEnumerable(),
#   as in items.AsStackEnumerable().Where(static x => x.IsValid).Select(static x => x.Name).AddTo(names).
#   Use static lambdas and the state overloads (.Any(name, static (a, n) => a.Name == n)) so no closure is allocated.
#   The compiler (netstandard2.0) uses the embedded copy Kassyi.ZeroAlloc.Linq.Embedded, imported globally.
# Not a fix: rewriting the query as a hand-written for / foreach loop. It is the same query, longer and harder to
#   check. Keep a loop only where .agents/rules/coding-style.md 2.4 keeps one (output written while iterating, ref
#   locals, several out values, neighbouring elements, grouping into a dictionary).
